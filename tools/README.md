# Инструменты уровней: проверка, боты, подбор ходов

Всё на чистом Lua и работает на LuaJIT (быстро) и Lua 5.1. Ядро используется только через публичный API `core/game.lua` (`core.load_level`, `core.new`, методы игры, `clone{reseed}`, `set_timing`). Команды запускаются из корня репозитория.

| Файл | Что делает |
|---|---|
| `tools/levels.lua` | проверка уровней, статистика, ASCII-превью |
| `tools/bot/bot.lua` | боты `greedy` (средний игрок) и `strong` (опытный) |
| `tools/bot/run.lua` | одна партия бота: результат, `moves_to_win`, след по ходам |
| `tools/bot/tune.lua` | подбор ходов по распределению `moves_to_win`, отчёт, `--write` |
| `tools/bot/common.lua` | общие функции: чтение уровней, замена `moves`, JSON, генератор бота |

## Проверка уровней

```sh
luajit tools/levels.lua validate              # все content/levels/level_*.json
luajit tools/levels.lua validate 5 12-15      # выбранные уровни (или пути к файлам)
luajit tools/levels.lua validate --strict     # замечания по плану считаются ошибками
luajit tools/levels.lua stats                 # сложности, звёзды, элементы по уровням (--json)
luajit tools/levels.lua preview 25            # поле по JSON (координаты с нуля, как в файле)
luajit tools/levels.lua preview 30 --seed 3   # стартовая доска, которую ядро строит для сида
```

- `validate` грузит каждый файл через `core.load_level` (все правила 2.1 `core-rules.md`) и печатает ошибки ядра; ещё проверяет, что `id` совпадает с номером в имени файла. Код выхода 1, если есть ошибки.
- Замечания по `levels-plan.md` (не ошибки): сложность по «пиле», число цветов по диапазону уровней, ходы вне 20–35.
- `stats`: число уровней каждой сложности, сумма звёзд (easy и medium — 1, hard — 2, super_hard — 3; по плану к 100-му уровню 126), таблица «размер, цвета, ходы, цели, элементы», первое появление каждого элемента.
- Превью: каждая клетка — 4 символа. Первый — содержимое (`r o y g b p` — цвет фишки, `+` — случайная фишка, `R/S/B/D` — Рифф/Сабвуфер/Пташка/Диско-шар, `M` — микрофон, `X` — коробка, `K` — тумба, `N` — помехи, `A` — шарик, `C` — колонка). Второй — подробность (hp, цвет шарика, ось Риффа `-`/`|`, `e` — стойка). Третий — плитка танцпола (`_` hp 1, `=` hp 2). Четвёртый — провода (`w` hp 1, `W` hp 2). `v` над столбцом — спавнер, `.` — пустота.

## Боты

```sh
luajit tools/bot/run.lua 25                          # одна партия, сид 1, жадный бот
luajit tools/bot/run.lua 25 --seed 7 --bot strong    # сильный бот
luajit tools/bot/run.lua 25 --games 20               # 20 партий подряд (сиды 1..20) и скорость
luajit tools/bot/run.lua 25 --json                   # запись партии в JSON
luajit tools/bot/run.lua 25 --turbo                  # настоящая игра тоже в турбо (быстрее, для отладки)
```

Опции: `--seed` (сид игры), `--bot-seed` (сид бота, по умолчанию равен сиду игры), `--budget` (бюджет ходов, по умолчанию 200).

**Как бот выбирает ход.** В покое бот перебирает:
- все пары `game:moves()`, включая свапы со спецфишками и свапы двух спецфишек (комбо);
- тапы по свободным спецфишкам.

Каждый ход проверяется на своём клоне: `game:clone{reseed = k}` → `set_timing("turbo")` → команда → до покоя. Клон пересеян, поэтому будущие цвета настоящей игры боту неизвестны (17.3).

Оценка хода (план, стр. 26): прогресс целей × 10 + созданные спецфишки × 3 + волны каскада, плюс бонус за комбо. Если целей несколько, каждая считается в своих единицах, нормированных так, что средняя единица весит 1.
- `greedy`: с вероятностью 70% берёт лучший ход, иначе случайный из трёх лучших. Случайность — свой генератор бота (MINSTD), независимый от потоков игры.
- `strong`: всегда лучший ход. Победа +1000, комбо весят больше, крупные спецфишки и спецфишки рядом с целями (≤ 2 клеток до плитки, блокера цели или микрофона) — тоже. Для трёх лучших ходов есть второй ход: только свапы, которые по доске создают спецфишку или комбо (не больше трёх клонов на ветку).
- При равенстве берётся ход, который раньше в списке. Очки целые, поэтому бот детерминирован при заданных (уровень, сид игры, сид бота) на обеих ВМ.

**Настоящая игра** идёт в обычных таймингах (решение №5 журнала; турбо — только в просмотре ходов), если нет `--turbo`.

**Неограниченный бюджет** нужен, чтобы получить `moves_to_win` — сколько ходов понадобилось боту. Уровень грузится из своего же JSON, где заменено только значение `moves` на `min(бюджет, 60)` (схема допускает 5..60). Дальше при `out_of_moves` бот посылает публичную команду `continue {moves = n}`, пока бюджет не кончится. Ядро читает `moves_left` только в проверке «ходы кончились» и в финальном концерте. Поэтому первые 60 ходов совпадают с партией при любом лимите M ≤ 60, и победа при лимите M — это ровно `moves_to_win ≤ M`.

**Запись партии** (`Run.play`, `--json`):

| Поле | Что значит |
|---|---|
| `won`, `moves_used`, `duration` | итог первой попытки с лимитом уровня; длительность в тиках до победы или до последнего хода |
| `moves_to_win` | ходов до победы при бюджете; `nil`, если победы нет |
| `ending` | `won` \| `stuck` (нет ходов и продолжения) \| `budget` \| `timeout` |
| `remaining[k]` | доля оставшихся целей после хода k: среднее по целям `осталось / было`, 0 — всё выполнено |
| `specials[k]`, `waves[k]`, `ticks[k]` | спецфишки хода, наибольшая волна каскада хода, тик покоя после хода |
| `specials_total`, `cascades` | за первую попытку; `cascades` — ходы с волной ≥ 2 |
| `evals` | сколько клонов просчитал бот |

## Подбор ходов

```sh
luajit tools/bot/tune.lua --n 100 --jobs 3                  # пробный прогон всех уровней
luajit tools/bot/tune.lua --levels 21-30 --n 300 --jobs 3   # часть уровней
luajit tools/bot/tune.lua --n 300 --jobs 3 --write          # записать подобранные ходы в файлы
```

Опции:
- `--bot greedy|strong` (по умолчанию `greedy`);
- `--budget` (по умолчанию 120: вдвое больше предела 60, этого хватает для любого M);
- `--dir` (по умолчанию `content/levels`);
- `--md`, `--json` — пути отчётов; `--no-report` — без отчётов;
- `--vm` — интерпретатор рабочих процессов (по умолчанию `luajit`);
- `--quiet` — без строк о ходе работы.

**Как считается.**
1. Для каждого уровня играются N партий: сиды игры и бота 1..N, одинаковые для всех уровней и прогонов (общие случайные числа). Бюджет ходов фактически неограничен.
2. Доля побед с первой попытки при лимите M = доля партий с `moves_to_win ≤ M`. Одно распределение сразу даёт кривую для всех M.
3. M ищется в 5..60, чтобы доля побед была ближе всего к центру коридора: easy 90% (85–95), medium 68% (60–75), hard 42% (35–50), super_hard 25% (20–30).
4. Если на эту кривую ложится целая «полка» одинаковых M:
   - полка на цели или выше — берётся её наименьший M;
   - полка ниже цели — наибольший (настоящая кривая растёт по полке);
   - если полка ниже цели тянется до 60 и лежит в коридоре, берётся её наименьший M: лишние ходы ни разу не помогли.
5. Для выбранного M считаются:
   - ожидаемое число попыток `1/p`;
   - доля близких проигрышей: среди проигрышей при M — те, у кого после M ходов осталось ≤ 20% целей (правило 4 плана);
   - медиана ходов у победителей.

**Флаги:**
- `too_hard` — даже при 60 ходах ниже коридора (M = 60);
- `too_easy` — даже при 5 ходах выше коридора;
- `off_corridor` — кривая перепрыгивает коридор (мало партий или ступенька);
- `outside_band` — M вне 20–35 ходов плана;
- `near_miss_low` — близких проигрышей меньше половины;
- `invalid` — уровень не загружается или партия упала с ошибкой ядра.

У целей из нескольких штук (например, `deliver 3`) один оставшийся предмет — это уже больше 20%, поэтому `near_miss_low` там ожидаем.

**Параллельность.** `--jobs K` запускает K рабочих процессов (`luajit tools/bot/tune.lua --worker ...` через `io.popen`) на непересекающихся наборах уровней. Наборы уравнены по оценке стоимости: сложность × площадь поля. Каждый процесс печатает результаты в JSON, главный их сливает. Строки о ходе работы идут в stderr.

**Отчёты.**
- Без `--write` файлы уровней не меняются. Отчёт — `docs/levels/tuning.md` (таблица: id, сложность, ходы было → стало, доля побед при M и при старом лимите, попытки, близкие проигрыши, медиана, время, флаги). Машиночитаемый результат — `docs/levels/tuning.json`.
- С `--write` в каждом файле уровня заменяются только цифры значения `"moves"`, остальной файл остаётся байт в байт. Перед записью текст проверяется через `core.load_level`. Результат пишется в `content/levels/tuning.json`.

**Скорость.** Под LuaJIT инструменты расширяют пределы JIT (`maxtrace=8000`, `maxmcode=32768`, `common.jit_opts`). Со стандартными 512 КБ машинного кода JIT постоянно сбрасывается, и LuaJIT работает медленнее интерпретатора. Около 40% времени уходит на `clone()` (глубокая копия состояния в ядре). Цифры и прогноз для 100 уровней — в конце `docs/levels/tuning.md`.

## Тесты

`tests/tools/*_test.lua` запускаются общим раннером: `./tools/test.sh --filter tools` (обе ВМ). Что проверяется:
- детерминизм ботов и совпадение партий на Lua 5.1 и LuaJIT (тест запускает обе ВМ);
- математика долей побед и выбор M по коридору;
- `--write` не трогает ничего, кроме `moves`;
- CLI уровней;
- замер скорости: печатает партии/с на текущей ВМ.
