# Как добавить партию уровней и район

Игра не ограничена сотней уровней. Число уровней и границы районов берутся из данных, правок кода не нужно (WP-13). Здесь шаги по порядку; формат файла уровня и правила описаны в `docs/levels/README.md`, `docs/design/core-rules.md` и `tools/README.md`.

## Что где лежит

| Что | Где | Кто читает |
|---|---|---|
| сам уровень | `content/levels/level_NNNN.json` (NNNN с нулями: `level_0101.json`) | ядро, экран уровня |
| пороги звёзд | `content/levels/stars.json` (запись на каждый уровень) | звёзды по очкам, концерты |
| районы: границы, задачи, сундук, жанр, песни | `content/districts.json` | мета, город, джукбокс, блокнот |
| карта: узлы и дорога | `content/map.json` (пишет `python3 tools/gen_map.py`) | экран карты |
| строки песни и названия | `client/i18n_songbook.lua` (en, ru) и `client/i18n_ko.lua` (ko) | блокнот |

**Правило числа уровней.** Уровней ровно столько, каков последний уровень последнего района в `content/districts.json` (поле `last`). У каждого района есть `first` и `last`: районы идут по порядку, первый начинается с уровня 1, каждый следующий с уровня после последнего у предыдущего, без пропусков и наложений. Размер района любой, но **не больше 32 уровней**: у района одна строка песни на уровень, а в наборе 32 строки (`C.songbook.pool`).

Число 100 и «пять районов» из кода убраны: `meta/config.lua` берёт их из `districts.json` при запуске (`C.bind_districts`).

## Шаги

### А. Только новые уровни в последнем районе (если в нём меньше 32 уровней)

1. Положите файлы `level_NNNN.json` подряд, без пропусков.
2. Проверьте: `luajit tools/levels.lua validate --strict`.
3. Подберите ходы ботами (`tools/bot/tune.lua`, как для уровней 41–100, `tools/README.md`).
4. Допишите пороги звёзд: `luajit tools/stars.lua gen` (в `stars.json` появится запись на каждый новый уровень; `kind` концертного уровня только `concert`, и он обязан быть `super_hard`).
5. Поднимите `last` последнего района в `content/districts.json` до номера последнего нового уровня.
6. Пересоберите карту: `python3 tools/gen_map.py`.
7. Проверки (раздел «Проверки»).

### Б. Новый район (нужен, если последний район уже полон или нужна новая тема)

1. Сделайте шаги 1–4 для уровней нового района.
2. Допишите район в **конец** списка `districts` в `content/districts.json` по образцу существующих:
   - `id` (латиницей, без пробелов, новый); `first` и `last` (сразу после предыдущего, не больше 32 уровней);
   - `map_tint` (цвет оттенка фона карты, например `"#E6E1F2"`; без него берётся этот же);
   - `name`, `genre` на ru, en, ko; `bpm`, `key`, `semitones_from_c`, `bars`, `mood`;
   - `tasks`: у первой задачи цена 1 звезда; каждая со `stem` (слой музыки района), `name` на ru, en, ko;
   - `chest` (монеты и бустеры), `songs` (песни этого жанра для джукбокса).
3. **Тексты блокнота** для нового района (иначе валидатор ругается): в `client/i18n_songbook.lua` ключи `sb.<id>.1` … `sb.<id>.32` (en, ru; строка 3–8 слов или одно слово, без настоящих текстов песен) и `sbt.<id>.1` … `sbt.<id>.16` (названия); в `client/i18n_ko.lua` те же ключи по-корейски (читает носитель).
4. **Арт района** (картинки кладёт `tools/art` или присылает продюсер, потом `python3 tools/gen_defold.py`): `districts/<id>/bg`, `bg_concert`, предметы задач и их `_ghost`; для карты `mapbg/bg_<id>`, `mapbg/gate_<id>`, `map/deco_<id>_1…6`.
5. **Музыка района**: стемы по задачам и песни джукбокса через `tools/audio/gen_audio.py` (WP-6).
6. `python3 tools/gen_map.py` и проверки.

## Проверки (все должны быть зелёными)

```sh
luajit tools/check_content.lua            # уровни, звёзды, карта, районы, тексты блокнота согласованы; сообщение называет файл и номер
luajit tools/levels.lua validate --strict # правила уровней, звёзды воспроизводятся ботом
python3 tools/gen_map.py --check          # карта не устарела
python3 tools/gen_defold.py --check       # сгенерированные ресурсы Defold
luajit tools/check_refs.lua               # картинки, звуки и стемы района на месте
./tools/test.sh                           # все тесты на Lua 5.1 и LuaJIT (в них входит check_content)
```

Что делает `check_content.lua`: уровни идут подряд от 1 до N и каждому уровню есть район; нет файла уровня за пределами N; в `stars.json` запись на каждый уровень и ни на какой лишний; в `map.json` N узлов и те же районы с теми же `first` и `last`; у каждого района есть названия на трёх языках, задачи, сундук, жанр и все строки блокнота.

## Как игра ведёт себя на конце контента

- После последнего уровня окно итогов, город и карта говорят «Скоро новые уровни»: это состояние `all_done` меты, оно зависит от N из данных.
- Когда в сборке появились новые уровни, игрок с прежним прогрессом продолжает с первого непройденного: прогресс не меняется, `all_done` исчезает сам.
- Игрок с прогрессом из сборки, где уровней больше, в сборке с меньшим числом уровней ничего не теряет: прогресс (`beaten`, монеты, звёзды) остаётся нетронутым.
- Формат сохранения не меняется. Новые районы получают свою запись при первой загрузке.

## Чего не делать

- Не менять файлы уровней 1–100 и порядок районов; не менять `id` района (по нему лежит прогресс игрока).
- Не пропускать номера уровней и не оставлять файл уровня вне района.
- Не вносить правок в `assets/gen/` и `client/assets_index.lua` руками: их пишет `tools/gen_defold.py`.
