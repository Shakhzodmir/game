# GLOW audio report

Generated by `tools/audio/gen_audio.py` (numpy synthesis, deterministic). All numbers below are measured
on the **decoded Ogg Vorbis files**, i.e. what the game actually plays. Re-run the script to refresh.

Meters (`tools/audio/analysis.py`): **LUFS** = ITU-R BS.1770-4 loudness; **M-max** = the loudest 400 ms
(momentary maximum); **phone** = the same after a 4th-order 300 Hz high-pass, a rough phone-speaker model;
**dBTP** = 4x oversampled true peak (what a resampling mixer can reach). SFX loudness targets use the
generator's gated K-weighted meter with 50 ms windows (`dsp.loudness`).

**Total size:** 5.87 MB of 7 MB budget (66 notes, 40 SFX, 48 music stems).

### 1.1 Headroom: notes that start together

music in a level at -6 dB. The table is the worst true peak over every step, colour

## 3. District music

Mono, Vorbis q0.3, 22.05 kHz; the bright stems (hats, shakers, tambourine, arpeggios, snaps, the café twinkle and
every party stem) are 44.1 kHz so they keep their 11–16 kHz sparkle. The loop is `round(bars × 4 × 60 / bpm ×
22050)` samples on the 22.05 kHz grid and exactly twice that at 44.1 kHz, so all stems of a district have
exactly the same duration; for 104 and 110 BPM the loop is rounded to the nearest 22.05 kHz sample (< 23 µs)
and the beat grid is stretched by that amount. Events that ring past the loop end wrap to the start and every
effect is circular, so each stem is exactly periodic.

**Balance:** stems are first set to relative loudness targets (`music.LOUDNESS`; sparse layers of expensive tasks
sit 3–6 dB hotter so an unlock is heard), then each district is scaled by **one common factor** so the loudest
combination the game plays — task stems, + tension (last moves), + party (finale) — has a true peak of -1.15 dBTP
(check: ≤ -1.0 dBTP and ≤ -1.0 dBFS sample peak, measured after exact 2x upsampling of the
22.05 kHz stems, i.e. as a resampling mixer sees it). All stems summed (never played) is listed for information.

Seam check (decoded files): *step/beats* = |x[0] − x[end]| / largest sample step within ±3 ms of any other beat
line; *click/beats* = 2nd-difference energy across the seam / largest such value on the other beat lines (pass
≤ 1.5). *Codec edge* = Vorbis coding error in the first/last 10 ms / 99th percentile of that error over the file.
*In-scale %* = share of the 6 strongest spectral peaks per frame (80 Hz–2 kHz) on the district's major scale
(drum and noise stems naturally score lower; jazz dominants deliberately use altered tones).

**Unlock audibility** (below each district): *stem vs mix* = the stem's loudness relative to the mix it joins;
*Δ mix* = how much the mix loudness rises when it unlocks (sparse layers such as shouts or risers add little
integrated loudness even when clearly heard, so both are listed).

## 5. Engine requirements and known limitations

- The headroom above holds only if the engine follows `manifest.json` → `mixer`: music at -6 dB in a level, match notes of one tick de-duplicated, at most 3 voices, strummed and attenuated as listed. Tension and party are never played together.
- Effects marked key C (`tap`, `swap_fail`, `sub`, `bird`, `moves_low`, the bells and fanfares, …) are written in C
  and must be transposed to the district key with playback speed exactly like the notes; played untransposed
  they clash with some district keys (e.g. `moves_low` over the A and E tension stems).
- Stems of one district have different sample rates (22.05 or 44.1 kHz) but exactly the same duration;
  start them in the same frame as before. Worth one on-device test that Defold honours the Ogg end-of-stream
  trim (the decoded length must equal `samples`), otherwise loops would drift.
- Vorbis coding noise at the loop seam of a few very quiet, band-limited stems (e.g. `jazz/organ`,
  `cafe/bass`) is at about −75 to −90 dBFS: inaudible under the mix, so it is left as is (Vorbis cannot start
  decoding in the middle of an encoded pre-roll without a decoder-side trim, which is riskier than the noise).

## 6. Replacing the placeholders

Keep the file names, formats and loop durations; `assets/sounds/manifest.json` lists every file (with its sample
rate) and the mixer contract. Music stems of one district must stay exactly the same duration and start on the
same downbeat. Notes and key-C effects must stay in C (the engine transposes them). Re-run
`python3 tools/audio/gen_audio.py` any time to restore the placeholders.
