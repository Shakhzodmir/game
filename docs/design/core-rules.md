# Правила доски GLOW — точная спецификация ядра (v3.1)

Этот документ — контракт для ядра `core/` (чистый Lua), ботов и клиента. Здесь нет «примерно»: любая ситуация на доске должна однозначно следовать из правил ниже. Если код и документ расходятся, это баг одного из них; исправление фиксируется в обоих. Имена и id — по глоссарию из `decisions.md`. Изменения относительно v2 перечислены в `decisions.md`, раздел 7.

---

## 0. Основы

- **Тик.** Симуляция идёт фиксированными тиками, 60 в секунду. Всё время в ядре измеряется в тиках. Точная семантика времени — раздел 15.1.
- **Единицы.** 1 клетка = 3600 единиц. Все координаты, смещения и скорости — целые числа. Бесконечностей и дробей в состоянии нет.
- **Координаты API.** `x` — колонка, 1..W слева направо; `y` — ряд, 1..H сверху вниз. Индекс клетки `i = (y-1)*W + x`. В JSON уровня координаты считаются с нуля (раздел 2), загрузчик переводит их в 1-базовые.
- **Порядок обхода.** Везде, где порядок влияет на результат, обход идёт по возрастанию индекса клетки, если не сказано иное.
- **Цвета.** Глобальный порядок: `red`=1, `orange`=2, `yellow`=3, `green`=4, `blue`=5, `purple`=6. Ничьи между цветами решаются в пользу меньшего номера.
- **Детерминизм.** Результат однозначно определяется уровнем, сидом, уровнем помощи, бустерами перед уровнем, режимом таймингов, флагом `input_lock` и списком принятых команд с номерами тиков (раздел 17).
- **Правила кода ядра** (проверяются линт-тестом):
  1. Нет `pairs`/`next` там, где порядок влияет на результат: только массивы и циклы по индексу.
  2. Нет `#` на таблицах, где могут быть `nil`. Массивы доски имеют фиксированный размер W·H, пустота — `false` или 0.
  3. Каждый компаратор `table.sort` — строгий полный порядок, последний ключ — индекс клетки или id.
  4. Никаких сравнений строк в логике: только числовые id и перечисления (коды — 17.2).
  5. Нет `math.random`, `os.*`, `tostring` дробных чисел в логике.
  6. Числа ≥ 2^31 сериализуются через `string.format('%.0f', v)` (на wasm32 `%d` обрезается до 32 бит).
  7. Состояние — только простые данные (числа, булевы, массивы и таблицы из них), без замыканий и метатаблиц. Это нужно для `clone` и хеша.

### 0.1 Словарь

| Термин | Значение |
|---|---|
| подвижная фишка | `regular`, `special` или `mic` без проводов |
| объект | содержимое одной клетки; колонка 2×2 — один объект на четыре клетки |
| ключ объекта | индекс его клетки; у колонки — индекс её левой верхней клетки |
| одноклеточный блокер | `record_box`, `concrete`, `noise`, `balloon` |
| отрезок | максимальная вертикальная последовательность существующих клеток в одной колонке |
| верх / низ отрезка | его клетка с наименьшим / наибольшим `y` |
| открытый слот | пустой слот, либо фишка или блокер в состоянии `fall`, `swap`, `clear` или `armed` |
| дыра | существующая пустая клетка, которую гравитация не может заполнить (10.1) |
| источник | то, что наносит удары (раздел 7) |
| запись | элемент очереди планировщика (15.1, 15.2) |
| `now` | номер выполняемого тика (15.1) |
| открытая цель | цель с остатком > 0 |

## 1. Модель поля

Клетка существует или нет (пустота `.`). У существующей клетки три слоя:

| Слой | Что хранит |
|---|---|
| Пол (`floor`) | Танцпол: прочность `hp` 1–2. Плитка «зажигается», когда `hp` падает до 0 |
| Слот (`slot`) | Одна фишка или блокер, либо ничего |
| Покрытие (`overlay`) | Провода: прочность 1–2, только поверх обычной фишки |

Статические свойства клетки: `spawner` (сюда сверху входят новые фишки), `exit` (стойка микрофона). Метка освобождения `vac` (1.3).

### 1.1 Виды содержимого слота (`kind`)

| kind | Примеры | Падает | Свап / тап | Матчится | Удар `effect` по ней |
|---|---|---|---|---|---|
| `regular` | 6 цветов | да | свап | да | уничтожается |
| `special` | riff, sub, bird, disco | да | свап и тап | нет | запуск (7.2) |
| `mic` | микрофон | да | свап | нет | ничего |
| `blocker` | record_box, concrete, noise, balloon, column | нет | нет | нет | по таблице 7.3 |

Обычная фишка под проводами не падает, не свапается, не бывает донором, но матчится на месте. Провода бывают только над `regular`.

### 1.2 Состояния и флаги

| state | Значение | Матчится | Ввод | Удар |
|---|---|---|---|---|
| `idle` | покой | да (`regular`) | да | обычный |
| `fall` | летит в свою целевую клетку | нет | нет | открытый слот |
| `swap` | свап, откат, неудачный свап или блокировка после перемешивания | нет | нет | открытый слот |
| `clear` | уничтожена или снята, исчезнет через `T.clear` | нет | нет | открытый слот |
| `armed` | спецфишка запущена и ждёт удара по своей клетке (7.2) | нет | нет | открытый слот |

- Целый (неразрушенный) блокер всегда `idle`. Разрушенный блокер переходит в `clear`, как фишка. У колонки 2×2 все четыре клетки переходят в `clear` и пустеют вместе.
- Фишка в `fall` уже записана в свою **целевую** клетку; отставание хранится смещениями `offy ≥ 0` и `offx` в единицах. Визуальный центр = центр целевой клетки минус смещение: `vis_y = y·3600 − offy`, `vis_x = x·3600 − offx`.
- У фишки есть `settle_tick` — тик, когда она последний раз стала `idle` (0 для стартовой доски).
- **Флаг `pinned`.** У фишки в `idle` есть множество источников `pins` (массив id источников по возрастанию). Фишка «закреплена», если оно не пусто. Закреплённая фишка:
  1. не свапается и не тапается;
  2. не падает и не бывает донором по диагонали (для гравитации — `wait`);
  3. не попадает в списки других диско-шаров и «Цвет X», в кандидаты Пташки и в подсчёт «самого частого цвета»;
  4. матчится как обычно и получает удары как обычно.

  Кто закрепляет: 7.2.7 (пути эффектов и прожекторов), 8.3 (цель Пташки), 8.4–8.5 (списки L). Источник снимает свою отметку, когда наносит удар по клетке фишки или когда его шаг для этой фишки пропускается. Когда фишка перестаёт быть `idle` (уничтожена, взведена, превращена), все её отметки снимаются.

### 1.3 Метки хода и волны

Метка — пара `(mv, wv)`: номер действия и волна. Сравнение лексикографическое, `max` — по нему.

1. **Действия.** Счётчик `act` растёт на 1 при каждом принятом свапе (кроме неудачного), тапе (включая свайп спецфишки, 5.1.5) и бустере. `continue`, `give_up`, `skip` и неудачный свап действий не создают. Свап и тап запоминают свой номер `a` = значение `act` сразу после увеличения.
2. **Начальные значения.** У каждой фишки и каждого блокера стартовой доски метка `(0, 0)`, у каждой клетки `vac = (0, 0)`.
3. **Свап.** При принятии свапа запоминаются метки обеих фишек. В тике подтверждения (5.1.3) обе получают `(a, 0)`, где `a` — номер **этого** свапа (не текущее значение `act`). При откате обе сразу получают обратно запомненные метки: номер возвращённого действия не остаётся ни в одной метке.
4. **Освобождение клетки не гравитацией.** Клетка получает `vac` = метка причины:
   - удар уничтожил содержимое — метка источника удара (для колонки 2×2 — все четыре клетки);
   - спецфишка или обе спецфишки комбо сняты при срабатывании (7.2.4) — метка активации;
   - микрофон доставлен — метка микрофона.
5. **Гравитация.** Фишка `P` переходит из клетки `S` в клетку `T`. При вертикальном переносе `P.метка = max(P.метка, T.vac, vac каждой клетки строго между S и T)`; при диагональном — `max(P.метка, T.vac)`. Затем `S.vac = P.метка`.
6. **Спавн.** Новая фишка в клетке `c` получает метку `max(c.vac, vac каждой клетки отрезка выше c)`.
7. **Провода.** Когда удар источника `s` снимает последний слой проводов, `P.метка = max(P.метка, метка s)`.
8. **Метка группы** (раздел 6): `M` = max `mv` по фишкам группы; `W` = 1 + max `wv` по фишкам группы с `mv == M`. Новая спецфишка группы получает `(M, W)`.
9. **Метки источников.** `match` и `adjacent` — метка группы. Активация спецфишки (метка запуска):
   - свап и тап — `(a, 1)` со своим номером `a`; бустер — `(act, 1)` в момент принятия;
   - цепочка — метка удара, который её взвёл;
   - груз Пташки — метка Пташки; спецфишки, превращённые комбо «Цвет X», — метка комбо;
   - финальный концерт — `(A + 1, 1)`, где `A` — последний номер действия.
10. **Слияние ходов.** Если правило 5 или 7 поднимает `mv` фишки с `m` до `m' > m`, а действия `m` и `m'` оба стоят в очереди конца хода (раздел 11), то `merged[m] = max(merged[m], m')`: каскад хода `m` влился в каскад хода `m'`.

Волна `W` определяет очки (`20 × W` за фишку), высоту ноты (ступень `min(W−1, 10)` пентатоники) и похвалы (раздел 16). Удар, снявший `hp` с целой помехи (7.3), ставит флаг `noise_hit` действию `m` своей метки `(m, w)`, если оно есть в очереди конца хода; иначе флаг никуда не пишется. Слитые ходы получают зачёт по цепочке `merged` (раздел 11).

### 1.4 Идентификаторы

1. **Объекты.** У каждой фишки и каждого блокера есть id; у колонки 2×2 — один id. Счётчик `next_piece_id` начинается с 1; выдача id — взять текущее значение и увеличить счётчик на 1.
2. **Старт.** В пункте 4.4, когда стартовая доска окончательна (после 4.3 вместе с перемешиванием, до бустеров 4.5), все объекты получают id по возрастанию своего ключа. Неудачные заполнения 4.3 id не тратят.
3. **Новый id** получают только новые объекты: каждый спавн (в порядке прохода 10.1) и каждая новая спецфишка группы (6.3).
4. **id и метка сохраняются** при движении (гравитация, свап, перестановка перемешивания) и при превращении на месте: бустер перед уровнем, Рифф продолжения, Рифф концерта (его метка задана в 13), Рифф перемешивания (12.2, пункты 3–5), превращение «Цвет X», фишка, ставшая помехой.
5. **Источники.** Счётчик `next_source_id` начинается с 1. Источник создаётся:
   - при разрешении группы — сначала `match`, затем `adjacent`;
   - при каждой состоявшейся активации — в начале её записи (у груза — внутри записи удара Пташки): одиночная спецфишка, комбо (один источник на эффект комбо), груз, каждая превращённая спецфишка, каждая активация концерта;
   - бустером — в начале его записи (5.3).
6. **Состояние источника:** id, вид (`match`, `adjacent`, `effect`), метка, цвет группы (или 0), флаг `all_layers` (8.5, «Гранд-финал»), `own` — id его собственных `armed` спецфишек (одна; у комбо две, первой — спецфишка в `to`; у груза, бустера, `match` и `adjacent` — ни одной; после снятия — ни одной), `centre` — клетка первой из `own` в момент активации, ключи дедупликации (7), резервы Пташек (9).
7. **Жизнь источника.** Источник активен, пока в очереди есть хотя бы одна его запись (записи видов 2–5 несут id источника первым полем, 15.2). `match` и `adjacent` живут только во время разрешения своей группы. Отметки `pins` и резервы всегда сопровождаются записью источника, поэтому у неактивного источника их нет.

## 2. Формат уровня (JSON)

```json
{
  "id": 42, "version": 1,
  "size": [9, 9],
  "moves": 28,
  "difficulty": "hard",
  "colors": ["red", "orange", "yellow", "blue", "purple"],
  "goals": [
    {"type": "collect", "color": "red", "count": 30},
    {"type": "break", "item": "record_box", "count": 18},
    {"type": "light"},
    {"type": "deliver", "count": 3}
  ],
  "cells": ["..#####..", ".#######.", "#########", "..."],
  "spawners": "top",
  "exits": "bottom",
  "floor":   [{"at": [3, 4], "hp": 2}],
  "overlay": [{"at": [2, 6], "type": "wires", "hp": 1}],
  "slots":   [
    {"at": [4, 4], "type": "record_box", "hp": 3},
    {"at": [0, 5], "type": "concrete", "hp": 2},
    {"at": [1, 1], "type": "noise"},
    {"at": [6, 2], "type": "balloon", "color": "red"},
    {"at": [3, 7], "type": "column", "hp": 8},
    {"at": [4, 0], "type": "riff", "axis": "h"},
    {"at": [5, 0], "type": "piece", "color": "blue"},
    {"at": [2, 0], "type": "mic"}
  ],
  "mic": {"total": 3, "on_board_max": 2, "gap_moves": 3},
  "spawn_weights": null
}
```

### 2.0 Схема

Любой ключ, не описанный здесь, — ошибка. Все числа — целые. `null` равносилен отсутствию ключа; `null` внутри массивов запрещён.

| Поле | Обяз. | Значение |
|---|---|---|
| `id`, `version` | да | целые ≥ 1 |
| `size` | да | `[W, H]`, 6 ≤ W ≤ 9, 6 ≤ H ≤ 11 |
| `cells` | да | H строк по W символов: `#` — клетка, `.` — пустота; `cells[y]` — ряд y |
| `moves` | да | 5..60 |
| `difficulty` | да | `easy` \| `medium` \| `hard` \| `super_hard` |
| `colors` | да | 4–6 разных id из шести цветов; порядок в массиве не важен, везде используется глобальный порядок |
| `goals` | да | 1–3 цели, не больше одной на пару (тип, цвет/предмет); номер цели — её позиция в массиве, с 1 |
| `spawners` | нет, `"top"` | `"top"` — самая верхняя существующая клетка каждой колонки; или список `[[x, y], …]` |
| `exits` | нет, `"bottom"` | `"bottom"` — низ каждого отрезка; или список. Используются только с целью `deliver` |
| `floor` | нет, `[]` | `{at, hp: 1..2}` |
| `overlay` | нет, `[]` | `{at, type: "wires", hp: 1..2}` |
| `slots` | нет, `[]` | см. ниже |
| `mic` | только при `deliver` | `{total, on_board_max ≥ 1, gap_moves ≥ 0}`, `total == deliver.count` |
| `spawn_weights` | нет, `null` | `null` — вес 1 у каждого цвета; иначе объект, ключи которого **ровно** цвета уровня, значения — целые 1..1000 |

- `at` = `[x, y]` с нуля: x — колонка слева направо, y — ряд сверху вниз.
- Типы `slots`: `record_box {hp 1..3}`, `concrete {hp 1..2}`, `noise {}`, `balloon {color}`, `column {hp 6..12}` (`at` — левая верхняя клетка, занимает 2×2), `riff {axis: "h"|"v"}`, `sub {}`, `bird {}`, `disco {}`, `piece {color}`, `mic {}`.
- Все перечисленные поля элементов (`at`, `hp`, `type`, `color`, `axis`) обязательны; значений по умолчанию у них нет.
- Цели: `collect {color, count ≥ 1}`, `break {item, count ≥ 1}`, `light {}` (зажечь все плитки уровня), `deliver {count ≥ 1}`.

### 2.1 Валидация (ошибка — уровень не загружается)

1. **Схема** по 2.0 и 2.2.
2. **Геометрия.** Все `at`, спавнеры и стойки — существующие клетки, без повторов. В одном слое у клетки не больше одного элемента. `column` занимает 4 существующие клетки без других элементов слота. Прямо над спавнером (`(x, y−1)`) — пустота или край поля.
3. **Провода** стоят только над клеткой, где будет обычная фишка: над клеткой случайного заполнения или над `piece`.
4. **Цвета** `balloon` и `piece` входят в `colors`.
5. **Цели.**
   - `collect.color` ∈ `colors`;
   - `break.item` ∈ {record_box, concrete, noise, balloon, column}, `count` ≤ числу таких объектов на старте (колонка — один объект);
   - `light` — на уровне есть хотя бы одна плитка;
   - `deliver` — есть блок `mic` и хотя бы одна стойка.
6. **Разных элементов** не больше трёх. Считаются: record_box, dancefloor, wires, mic, concrete, noise, balloon, column.
7. **Заполнимость.** Проверка на двух досках:
   - `B0` — уровень, из которого убраны все подвижные фишки (случайные, `piece` без проводов, спецфишки, микрофоны); блокеры и фишки под проводами остаются как неподвижное содержимое;
   - `B1` — то же, но убраны ещё все блокеры и фишки под проводами (остаются только пустоты).

   На каждой доске, начиная с тика 1, выполняются только шаги 4–6 (раздел 15) в турбо-режиме бесцветными фишками: без матчей, микрофонов и стоек. Прогон идёт до первого тика без назначений (не больше 1000 тиков, иначе ошибка). Уровень проходит, если в конце заняты все существующие свободные клетки `B0` и все существующие клетки `B1`.
8. **Микрофоны** (только при `deliver`; без `deliver` блок `mic` и фишки `mic` запрещены):
   - каждый низ отрезка, заполненный в проверке `B1`, — стойка (для явного списка тоже);
   - стойки и спавнеры не пересекаются;
   - ни один стартовый микрофон не стоит на стойке;
   - число стартовых микрофонов ≤ min(`on_board_max`, `total`).
9. **Стартовые фишки** (`piece`, с проводами и без) не образуют между собой линию из 3 или квадрат 2×2 одного цвета.
10. **Стартовая доска** строится по разделу 4 для `seed = 1..10`, и ни в одном случае перемешивание 4.3 не доходит до пункта 3 раздела 12.2.

### 2.2 Загрузчик и каноническая форма

- `core.load_level(text)` принимает текст JSON и проверяет его по потоку токенов (стандартный декодер Lua теряет эту информацию): `null` внутри массива, число с дробной частью или экспонентой, повтор ключа в объекте — ошибка.
- **Каноническая форма** (для хеша уровня, 17.1): проверенный объект; ключи со значением `null` и отсутствующие ключи опускаются, значения по умолчанию **не** добавляются; ключи объектов отсортированы по байтам; без пробелов и переводов строк; порядок массивов сохраняется; строки — как во входе (все строки схемы — ASCII), экранируются только `"` и `\`; целые — `string.format('%.0f', v)`.

## 3. Случайность

### 3.1 Генератор

- Генератор **MRG32k3a** (L'Ecuyer). Эталонный код (оператор `%` Lua; все промежуточные значения по модулю меньше 2^53, частное меньше 2^21, поэтому результат точный на Lua 5.1 и LuaJIT):

```
m1 = 4294967087; m2 = 4294944443
a12 = 1403580; a13 = 810728; a21 = 527612; a23 = 1370589
-- s[1..3] — компонента 1 (от старого к новому), s[4..6] — компонента 2
next_int():
  p1 = (a12*s[2] - a13*s[1]) % m1
  p2 = (a21*s[6] - a23*s[4]) % m2
  s[1], s[2], s[3] = s[2], s[3], p1
  s[4], s[5], s[6] = s[5], s[6], p2
  return (p1 - p2) % m1          -- целое в [0, m1-1]
int(n) = next_int() % n + 1      -- целое в [1, n]
```

- **Потоки:** `init` (стартовая доска вместе с её перемешиванием, бустеры перед уровнем, Рифф продолжения), `spawn` (цвета новых фишек и помощь), `effects` (цели Пташки, рост помех, выбор фишек концерта), `shuffle` (перемешивание в игре и Ремикс).
- **Инициализация потока** `k` (init=1, spawn=2, effects=3, shuffle=4):
  1. `x = (seed*7 + k*104729 + 12345) % 2147483647`; если `x == 0`, то `x = 1`.
  2. Шесть раз: `x = x*48271 % 2147483647`; результаты по порядку — `s[1]..s[6]`.
  3. Первые 8 выходов `next_int()` отбрасываются.
- **Сид попытки:** `h = 0; для v из (level_id, attempt, salt): h = (h*48271 + v + 1) % 2147483647`; `seed = h % 2147483646 + 1`. `salt` — целое в [0, 2^31−2], создаётся один раз при установке. `attempt` — номер начатой попытки на уровне, с 1. В реплее главный — записанный `seed`.

### 3.2 Случайный выбор

1. Любой случайный выбор из n ≥ 1 вариантов тратит ровно один `next_int` соответствующего потока и берёт вариант номер `int(n)` из списка, упорядоченного по индексу клетки (для цветов — по номеру цвета; для пар — по первому элементу, затем по второму). При n = 0 выбора и траты нет. Выбор «среди равных лучших» — тоже такой выбор: он тратит один `next_int`, даже если лучший вариант один.
2. **Взвешенный выбор цвета:** цвета перебираются в глобальном порядке; `r = next_int() % сумма_весов`; берётся первый цвет, у которого накопленная сумма весов > r.
3. **Самый частый цвет** `mf(filter)`: среди обычных фишек в `idle`, не закреплённых и подходящих под `filter`, цвет с наибольшим числом фишек; ничья — меньший номер; если таких фишек нет — «нет цвета». Фильтр по умолчанию включает фишки под проводами; для комбо «Цвет X» — только без проводов.

## 4. Стартовая доска

1. Из файла уровня ставятся фиксированные элементы: пол, слоты, покрытия. Все фишки `idle`, `settle_tick = 0`, метки и `vac` — `(0, 0)`.
2. **Заполнение.** Свободные существующие клетки заполняются по возрастанию индекса обычными фишками из потока `init`:
   - «разрешённые» цвета — цвета уровня, которые не дают линию из 3 с двумя соседями слева или с двумя соседями сверху и не дают квадрат 2×2 с левым, верхним и левым верхним соседом. Соседом считается любая обычная фишка, включая стартовые и под проводами;
   - если разрешённых нет — разрешены все цвета уровня;
   - один взвешенный выбор (3.2) среди разрешённых с весами `spawn_weights`.
3. **Проверка:** на поле нет ни одного матча и число ходов (12.1) не меньше 3. Всего не больше 100 заполнений (первое и до 99 повторов шага 2 с теми же фиксированными элементами; поток `init` продолжается). Если ни одно не прошло — перемешивание 12.2 сотого заполнения из потока `init`, без блокировки и без событий. Если после него на поле остался матч (это возможно, только если перемешивание дошло до пункта 3 раздела 12.2 или дальше), поле стартует «грязным» и матч разрешится в шаге 7 тика 1 с метками `(0, 0)`.
4. **id** всем объектам (1.4.2).
5. **Бустеры перед уровнем** (Рифф, Сабвуфер, Диско-шар) ставятся в порядке их списка в реплее, каждый одним выбором из потока `init`:
   - кандидаты — обычные фишки без проводов, не на плитке танцпола и не цвета из цели `collect`; если таких нет — любые обычные фишки без проводов;
   - фишка заменяется спецфишкой (id и метка сохраняются); у Риффа ось `h`, если это первый, третий или пятый Рифф в списке, иначе `v`;
   - если кандидатов нет совсем, бустер не ставится и попадает в список `unplaced` (17.3), чтобы мета его вернула.
6. `rest_flag = true` (5.3), если поле не стартует «грязным»; иначе `false`.

## 5. Ввод и действия

### 5.0 Команды

- `game:input(cmd)` вызывается между тиками. Возвращает `true, 'ok'` (команда принята), `true, 'fail'` (принят неудачный свап) или `false, reason`. Команда только проверяется и меняет состояния фишек, счётчики и очередь; ударов она не наносит (15.1). У команды `now = tick + 1`; события команды получают `t = now`.
- В реплей пишутся только принятые команды (включая неудачный свап) как пара `(now, cmd)`. Команды одного окна применяются в порядке вызова.
- **Где разрешены:**

  | Команда | Состояния | Прочие условия |
  |---|---|---|
  | `swap`, `tap` | `playing` | `moves_left > 0`; при `input_lock` — ещё `rest_flag` |
  | `booster` | `playing`, `out_of_moves` | `rest_flag` |
  | `continue` | `out_of_moves` | нет флага `stuck` (12.2) |
  | `give_up` | `out_of_moves` | — |
  | `skip` | `won_wait`, `concert` | — |

- **Причины отказа** проверяются в этом порядке; возвращается первая:
  1. `bad_cmd` — неизвестный тип команды или бустера, нет обязательного поля или оно не того типа, координата не целая, `row`/`col` вне поля, `continue.moves` вне 1..60;
  2. `bad_state` — команда не разрешена в текущем состоянии;
  3. `no_moves` — `swap` или `tap` при `moves_left == 0`;
  4. `not_rest` — `booster` (или `swap`/`tap` при `input_lock`) при `rest_flag = false`;
  5. `bad_cell` — клетки нет или она не подходит (5.1.1, 5.2, 5.3);
  6. `not_movable` — в клетке нет подходящей фишки (5.1.1, 5.2);
  7. `no_candidates` — Ремикс при n < 2 (5.3); `continue` при флаге `stuck`.
- **`input_lock`** — опция конструктора (17.3), по умолчанию `false`; пишется в заголовок реплея. При `true` свап и тап принимаются только при `rest_flag = true` — это запасной «блокирующий режим» из плана.

### 5.1 Свап `{type="swap", from={x,y}, to={x,y}}`

`from` — клетка, которую тянул игрок, `to` — соседняя по стороне клетка (координаты `to` могут быть вне поля).

**5.1.1 Проверки клеток** (после общих проверок 5.0, по порядку):
1. `from` не существует или `to` не соседняя по стороне с `from` — `bad_cell`.
2. В `from` спецфишка в `idle`, не закреплённая, а `to` вне поля, пустота, пустой слот, целый блокер или фишка под проводами — команда исполняется как тап по `from` (5.1.5).
3. `to` не существует — `bad_cell`.
4. В одной из клеток нет подвижной фишки (без проводов) в `idle`, не закреплённой, — `not_movable`.

**5.1.2 Оценка.**
- Участвует спецфишка — свап принят.
- Иначе виртуальный обмен на **ожидаемой доске** должен дать матч через `from` или `to`: линию ≥ 3 или квадрат 2×2 одного цвета среди обычных фишек. Ожидаемая доска: обычная фишка в `idle` (с проводами и закреплённая тоже) стоит в своей клетке; в `fall` — в своей целевой клетке; в `swap` — в клетке, где она окажется по окончании своего таймера (у свапа и отката — в клетке партнёра, у неудачного свапа и блокировки — в своей). Фишки в `clear` и `armed`, спецфишки, микрофоны и блокеры цвета не имеют. Есть матч — свап принят.
- Нет матча — **неудачный свап**: обе фишки в `swap` на `T.swap_fail` без обмена, потом снова `idle`. Действие не создаётся, ход не тратится. Событие `swap_fail`. Сюда же попадают свап двух обычных фишек одного цвета и свап двух микрофонов: игрок видит отскок.

В покое ожидаемая доска совпадает с доской фишек в `idle`, поэтому 12.1 и подсказка считаются по обычной доске.

**Принятый свап:** `act += 1`, свап запоминает `a = act`, `from`, `to` и метки обеих фишек; `moves_left -= 1`, `moves_made += 1`; действие `a` ставится в очередь конца хода (`noise_hit = false`, `merged = 0`). Обе фишки в `swap` на `T.swap`. События `swap`, `moves`.

**5.1.3 Окончание таймеров (шаг 2 тика).** Таймеры `swap`, `swap_fail`, `swap_back`, истекающие в `now`, обрабатываются в порядке их запуска, затем блокировки перемешивания — по индексу клетки:

```
для каждого истекающего таймера:
  swap:       фишки меняются клетками; обе получают (a, 0), где a — номер этого свапа;
              idle; settle_tick = now; есть спецфишка -> запуск (5.1.4)
  swap_fail:  обе фишки idle, settle_tick = now
  swap_back:  фишки меняются клетками обратно; idle; settle_tick = now
  блокировка: фишка idle, settle_tick = now
если истёк хотя бы один таймер:
  поиск и разрешение матчей по всему полю (раздел 6), правило 6.2.1 включено
  для каждого свапа без спецфишек, закончившегося в этом шаге (таймер swap), по возрастанию a:
    если ни from, ни to не входят ни в одну группу, разрешённую этим поиском -> откат
```

**Откат** (решение 13 журнала — всегда в пользу игрока): обе фишки получают запомненные метки, переходят в `swap` на `T.swap` (таймер `swap_back`) и в конце меняются клетками обратно; `moves_left += 1`, `moves_made -= 1`; действие `a` помечается «возвращённым» и убирается из очереди конца хода. События `swap_back`, `moves`. Откатов после `swap_back` нет; поиск шага 2 в тике окончания `swap_back` проверяет и эти фишки, как все остальные.

**5.1.4 Свап со спецфишкой.** В шаге 2, сразу после обмена:
- **две спецфишки** — комбо (8.5) с центром в клетке `to`. Обе спецфишки переходят в `armed`; запись `activate` (15.2) ставится на `now` с меткой `(a, 1)`: фишка — спецфишка в `to`, партнёр — клетка `from`;
- **спецфишка + другая фишка** — спецфишка переходит в `armed`, запись её активации ставится на `now` с меткой `(a, 1)`. Диско-шар со свапа с обычной фишкой запоминает её цвет как X (поле X записи); со свапа с микрофоном X выбирается при активации (8.4). Вторая фишка участвует в поиске матчей шага 2 как обычно.

Свап со спецфишкой никогда не откатывается.

**5.1.5 Свайп спецфишки в никуда.** В случае 5.1.1.2 команда исполняется ровно как тап по `from` (5.2): тратит ход, создаёт действие, метка `(a, 1)`. В реплей пишется исходная команда `swap`; при воспроизведении она проверяется так же.

### 5.2 Тап `{type="tap", at={x,y}}`

Проверки клетки: клетки нет — `bad_cell`; в ней нет спецфишки в `idle`, не закреплённой, — `not_movable`. Принятый тап: `act += 1`, тап запоминает `a = act`; `moves_left -= 1`, `moves_made += 1`; действие `a` ставится в очередь конца хода; спецфишка сразу переходит в `armed`, запись её активации ставится на `now` с меткой `(a, 1)`. Диско-шар от тапа выбирает X при активации. События `moves` (при принятии), `activate` (при активации).

### 5.3 Бустеры в уровне `{type="booster", booster=..., at={x,y} | row=y | col=x}`

- **Покой при вводе.** `rest_flag = true`, если поле было в покое в конце шага 8 последнего тика (после роста помех и перемешивания), и с тех пор не принято ни одной команды свапа (включая неудачный), тапа или бустера. Любая такая принятая команда ставит `rest_flag = false`.
- Бустер принимается в `playing` и `out_of_moves` при `rest_flag = true`. В `out_of_moves` принятый бустер переводит игру в `playing` (событие `state`); когда поле снова придёт в покой, шаг 8 при `moves_left == 0` вернёт `out_of_moves`, а выполненные цели — `won_wait`.
- Бустер создаёт действие (`act += 1`) для меток, но не тратит ход, не меняет `moves_made` и не ставится в очередь конца хода. Метка источника — `(act, 1)`.
- **Клетка с эффектом** — существующая клетка, в которой есть провода, или блокер, или обычная фишка, или спецфишка, или пустой слот над незажжённой плиткой. `stick` по клетке без эффекта и `row_light`/`col_light` по ряду/колонке, где нет ни одной клетки с эффектом, отклоняются с `bad_cell`. Так палочка не тратится впустую на микрофон или пустоту.
- Всё действие бустера — запись `booster` (15.2) на `now`, выполняется в шаге 3; в начале записи создаётся источник (1.4.5) и идёт событие `booster` (у Ремикса — после повторной проверки, см. ниже):
  - `stick` — один удар `effect` по клетке `at`;
  - `row_light` — удар `effect` по каждой существующей клетке `(x, row)` в тике `now + T.light_step·(x−1)`; пустоты пропускаются, но считаются в `x`. Один источник, пути закрепляются (7.2.7);
  - `col_light` — то же по колонке, тик `now + T.light_step·(y−1)`;
  - `remix` — перемешивание по 12.2 (пункты 1–3). Принимается, только если кандидатов перемешивания не меньше 2, иначе отказ `no_candidates`. При выполнении число кандидатов проверяется снова (свап в том же окне мог забрать фишки): если n < 2, Ремикс ничего не делает, событие `booster` с `ok = false`, предмет попадает в `unplaced`.

### 5.4 Служебные команды

- `continue {moves=n, riff=bool}` — только в `out_of_moves` без флага `stuck`: `moves_left += n`; если `riff`, одна обычная фишка без проводов в `idle` (выбор из потока `init`) становится Риффом с осью `h` (id и метка сохраняются, событие `continue_riff`); если кандидатов нет — Риффа нет, предмет попадает в `unplaced`. Состояние `playing`, флаг `stuck` снимается.
- `give_up` — из `out_of_moves` в `lost`.
- `skip` — в `won_wait` и `concert`: режим таймингов становится турбо до конца уровня (15.1, правило 8).

### 5.5 Выделение фишек в клиенте (обязательно для клиента)

Режимы ввода — решение 6 журнала. Ядро выделения не знает; клиент обязан вести его так:
1. Выделение привязано к id фишки и снимается, когда эта фишка перестаёт быть `idle` или уходит из своей клетки, либо игра выходит из `playing`.
2. Если выделена фишка S, тап по соседу N по стороне отправляет `swap{from=S, to=N}`, кем бы ни была N.
3. Режим «свайп»: тап по спецфишке без выделения или при несоседнем выделении снимает выделение и отправляет `tap`; тап по обычной фишке или микрофону выделяет её вместо прежней; тап по выделенной фишке снимает выделение.
4. Режим «тап-тап»: первый тап по любой фишке выделяет её; тап по выделенной спецфишке отправляет `tap`; тап по несоседней фишке переносит выделение.

## 6. Матчи

**Когда искать.**
- В шаге 2, если в нём истёк хотя бы один таймер (5.1.3). Только здесь действует правило 6.2.1.
- В шаге 7, если поле «грязное».

**Флаг «грязное».** Поле становится «грязным», когда любая фишка становится `idle` (приземление, конец любого таймера) или с фишки снимаются провода. Каждый поиск (в шаге 2 или 7), разрешив все свои группы, ставит флаг в `false`. Во время разрешения групп флаг не ставится: разрешение не может создать новый матч (фишка группы, освобождённая от проводов, уже входила в свои линии, а соседи её цвета — в ту же группу; новая спецфишка не матчится).

Поиск идёт **по всему полю** среди обычных фишек в `idle`, включая фишки под проводами и закреплённые. Реализация может проверять только линии и квадраты через клетки, изменившиеся с прошлого поиска, если результат тождественен полному поиску; это проверяет property-тест.

**Инвариант:** после поиска в шаге 2 и в шаге 7 среди фишек в `idle` нет ни одного матча.

**Группа.** Максимальные линии ≥ 3 одного цвета по горизонтали и вертикали плюс все квадраты 2×2 одного цвета. Линии и квадраты с общими клетками сливаются в одну группу. Все группы находятся на доске до начала разрешения, затем разрешаются по возрастанию наименьшего индекса своих клеток. Цвет группы — цвет её фишек.

### 6.1 Классификация (сверху вниз, первое совпадение)

| Условие в группе | Спецфишка |
|---|---|
| есть линия ≥ 5 | `disco` |
| есть горизонтальная линия ≥ 3 и вертикальная линия ≥ 3 | `sub` |
| есть линия ровно 4 | `riff`, ось = ось этой линии |
| есть квадрат 2×2 | `bird` |
| иначе | нет |

### 6.2 Клетка для спецфишки

Кандидаты — клетки группы **без проводов**. Если кандидатов нет, спецфишка и бонус не создаются. Иначе первое подходящее правило:
1. (только в шаге 2) Клетка группы, которая была `from` или `to` свапа, закончившегося в этом шаге (таймер `swap`). Если в группе клетки нескольких свапов — берётся свап с наименьшим `a`. Откаты и неудачные свапы не считаются. (Клеток одного свапа в группе не бывает больше одной: цвета двух фишек свапа разные.)
2. Для `sub` — кандидаты, лежащие одновременно в горизонтальной и вертикальной линии группы. Если их несколько — выбор по правилу 3 среди них; если нет ни одного — правило 3 среди всех кандидатов.
3. Кандидат с наибольшим `settle_tick`; при равенстве — ниже (больше y), затем левее (меньше x).

### 6.3 Разрешение группы (метка `(M, W)`)

1. Создаются источники `match`, затем `adjacent` (1.4.5) с меткой `(M, W)` и цветом группы. Событие `match`.
2. Клетки группы по возрастанию индекса получают удар `match` (раздел 7). Фишка в клетке спецфишки уничтожается без состояния `clear` — слот пустеет сразу; пол получает урон, цель и очки засчитываются, событие `clear`.
3. После всех клеток группы в клетку спецфишки ставится новая спецфишка: новый id, `idle`, метка `(M, W)`, `settle_tick = now`. События `special_new`, затем `score` с бонусом (7.4) в этой клетке.
4. Источник `adjacent`: один удар по каждой клетке вне группы, соседней по стороне хотя бы с одной клеткой группы, по возрастанию индекса. Колонка 2×2 получает не больше одного удара (дедупликация).
5. Похвала — раздел 16.

## 7. Удары

Удар — `hit(клетка, источник)`. Состояние источника — 1.4.6.

**Дедупликация.** Ключ удара — (источник, ключ объекта); источник запоминает его при первом ударе. Удар с уже использованным ключом пропускается целиком: ни проводов, ни слота, ни пола. Исключение — источник с флагом `all_layers`: у него ключ относится только к слою слота, а провода и пол каждой клетки бьются всегда.

### 7.1 Порядок обработки удара

0. **Снятие своей спецфишки** (7.2.4): если удар источника пришёл в его клетку `centre`, а `own` не пуст, сначала снимаются все спецфишки из `own`, и `own` становится пустым.
1. Открытость слота фиксируется здесь, **до** пункта 3, и дальше не пересчитывается.
2. **Провода.** Если на клетке провода: удар `adjacent` ничего не делает (удар закончен). Иначе `hp` проводов −1, событие `hit`; при 0 провода снимаются, событие `freed`, метка фишки по 1.3.7, поле «грязное» (кроме разрешения группы, раздел 6). Дальше обычный удар не идёт: фишка и пол защищены. Удар `all_layers` идёт дальше: к слоту — только если проводов больше нет, к полу — всегда.
3. **Слот** (для `all_layers` — только если ключ объекта ещё не использован этим источником):
   - открытый слот — ничего;
   - `regular` в `idle`: `adjacent` — ничего; `match` или `effect` — уничтожается;
   - `special` в `idle`: `effect` — запуск цепочкой (7.2.1); `match`, `adjacent` — ничего;
   - `mic` — ничего;
   - блокер — по таблице 7.3.
4. **Пол.** Плитка с `hp > 0` получает −1, если:
   - в пункте 3 уничтожено содержимое слота (при любом виде удара), **или**
   - удар `effect`, а слот был открыт (по пункту 1), **или**
   - у источника флаг `all_layers`.

   Урон полу — не больше одного за удар. Запуск спецфишки и её снятие полу урона не наносят. Каждый урон — событие `hit` (слой `floor`); при `hp == 0` — ещё `floor_lit`. Колонка — особый случай (7.3).

**Уничтожение** фишки или блокера: состояние `clear` на `T.clear`, потом слот пустеет. В момент уничтожения клетке ставится `vac` (1.3.4), засчитываются цели и очки (7.4), снимаются все отметки `pins`.

### 7.2 Жизненный цикл спецфишки

1. **Запуск.** Спецфишку запускают свап (5.1.4), тап (5.2, 5.1.5), удар `effect` по ней в `idle` (цепочка), комбо «Цвет X» (превращение) и финальный концерт. При запуске она сразу переходит в `armed`. Цепочка ставит запись активации на `now + T.chain` с меткой ударившего источника.
2. **Один раз.** Каждая спецфишка активируется не больше одного раза. Запуск уже `armed` спецфишки игнорируется; удар по ней — удар по открытому слоту.
3. **Ожидание.** `armed` спецфишка стоит в своей клетке (для гравитации — `wait`) до первого удара своего источника по своей клетке (`centre`):

   | Эффект | Удар по своей клетке |
   |---|---|
   | riff, bird | `t0` |
   | sub | `t0 + T.sub_swell` (кольцо 0) |
   | disco | после своего списка, `t0 + T.disco_step·#L` |
   | комбо | первый удар комбо по центру `to` (8.5) |

4. **Снятие.** Этот удар сначала снимает спецфишку: она переходит в `clear` на `T.clear`, как уничтоженная фишка (для гравитации — `wait`, для ударов — открытый слот); событие `clear` с `cause = fired`; очков, целей и урона полу нет; клетке ставится `vac` = метка активации. Затем удар идёт по уже открытому слоту по 7.1 (удар `effect` по открытому слоту наносит полу −1). У комбо первый удар по центру снимает обе спецфишки (обе в `clear`, `vac` обеих клеток = метка комбо); клетку `from` комбо бьёт, когда до неё доходит его геометрия. У груза Пташки своей спецфишки нет: его удар по своей клетке — обычный удар.
5. **Время `t0`** — тик, в шаге 3 которого выполняется запись активации (у груза — запись удара Пташки).
6. **Список действий.** При активации эффект строит полный список своих действий (ударов, шагов, превращений, запусков) в естественном порядке (задан в разделе 8) и устойчиво сортирует его по тику. Если один объект (у источника `all_layers` — одна клетка) попадает в список ударов дважды, остаётся первое вхождение. Действия с тиком `now` выполняются сразу, по порядку, внутри записи активации. Остальные ставятся в очередь по одной записи на действие (15.2), в этом порядке. Исключение — Пташка: её цели выбираются после выполнения креста (8.3).
7. **Закрепление пути.** В момент активации эффект закрепляет (1.2) каждую подвижную фишку в `idle` в каждой клетке, по которой он ударит в тике > `now` (так же закрепляют пути бустеры `row_light` и `col_light`). Удар по клетке снимает отметку этого источника. Так фишки на пути разряда, кольца или Пташки не уходят из-под удара, а колонка над сработавшей спецфишкой не падает в её клетку раньше, чем её накроет эффект.

### 7.3 Блокеры

| Блокер | hp | Ломается от | Особенности |
|---|---|---|---|
| `record_box` | 1–3 | `adjacent`, `effect` | −1 за удар |
| `concrete` | 1–2 | только `effect` | Учит копить спецфишки |
| `noise` | 1 | `adjacent`, `effect` | Удар, снявший `hp`, ставит `noise_hit` (1.3). Растёт в конце хода (раздел 11) |
| `balloon` | 1 | `adjacent` источника своего цвета, `effect` | |
| `column` (2×2) | 6–12 | `adjacent`, `effect` | Один удар на источник. При 0 все 4 клетки переходят в `clear`, получают `vac` = метка удара, и каждый из 4 полов получает ровно −1 (вместо урона полу по 7.1.4; у `all_layers` каждый пол бьётся своим ударом) |

Урон блокеру без разрушения — событие `hit` с остатком `hp`; разрушение — событие `destroy`. События колонки ставятся на её левую верхнюю клетку; урон её четырём полам — четыре события `hit` (слой `floor`) по индексу клеток.

### 7.4 Очки и цели

| Что | Очки |
|---|---|
| клетка группы, фишка которой уничтожена | `20 × W` |
| бонус группы за спецфишку | riff и bird — 60, sub — 90, disco — 150 |
| обычная фишка, уничтоженная ударом `effect` | 30 |
| превращение фишки комбо «Цвет X» | 30 |
| каждая единица `hp`, снятая с блокера (колонки тоже), проводов или плитки пола | 50 |
| Рифф финального концерта | 300 |
| всё остальное (доставка микрофона, активация и снятие спецфишки, рост помех, помеха перемешивания) | 0 |

Цели засчитываются в момент события:
- `collect` — обычная фишка цвета уничтожена (включая фишку в клетке новой спецфишки) или превращена комбо «Цвет X»;
- `break` — блокер разрушен (колонка — один объект); помеха, убранная перемешиванием (12.2.5), засчитывается, только если она была последней помехой на поле;
- `light` — плитка зажглась;
- `deliver` — микрофон доставлен.

Остаток цели не опускается ниже 0. Когда выполнена последняя цель, игра сразу переходит в `won_wait` (раздел 13).

## 8. Спецфишки и комбо

Общее для всех эффектов (7.2): `t0` — тик активации; у каждого эффекта свой источник вида `effect` с меткой запуска; список действий строится в естественном порядке, указанном ниже; `R(d) = (15·d + 6) // 7` — тик разряда на расстоянии `d` (28 клеток в секунду; в турбо 0). Удары бьют только существующие клетки; пустоты разряды пролетают насквозь, до края поля.

### 8.1 Рифф (`riff`, ось h или v)

- `t0`: удар по своей клетке. События `activate`, `bolt` по каждому из двух направлений.
- Клетки на расстоянии `d` вдоль оси в обе стороны — в тике `t0 + R(d)`.
- Естественный порядок: своя клетка, затем по `d`, при равном `d` — меньший индекс.

### 8.2 Сабвуфер (`sub`)

- `t0`: «набухание», события `activate`, `ring` (r = 0..2).
- Кольцо `r` (расстояние Чебышёва, r = 0..2, квадрат 5×5) — в тике `t0 + T.sub_swell + T.ring·r`. Кольцо 0 — своя клетка.
- Естественный порядок: по `r`, затем по индексу.

### 8.3 Пташка (`bird`)

1. `t0`: «крест» — своя клетка и 4 соседа по стороне, по индексу. Все удары креста выполняются сразу внутри записи активации.
2. Сразу после креста выбирается цель по разделу 9. Цель резервируется до удара; подвижная фишка в `idle` в клетке цели закрепляется этим источником. Событие `bird_fly`.
3. **Удар** — запись `bird_impact` на `t0 + T.bird_flight` (в турбо — выполняется сразу после выбора, внутри записи активации). При выполнении резерв и отметка снимаются, затем:
   - без груза — удар по клетке цели тем же источником (что бы в ней ни было);
   - с грузом (Рифф или Сабвуфер; груз бывает только у комбо, 8.5) — эффект груза активируется здесь же, внутри этой записи: новый источник с меткой Пташки, `t0` груза = этот тик, своя клетка груза — клетка цели. Рифф-груз бьёт по оси, выбранной в разделе 9.
4. **Целей нет:** без груза — только крест, события `bird_fly` нет; с грузом — запись `bird_impact` с клеткой центра комбо `to` на `t0 + T.bird_flight`, груз активируется в `to`; Рифф-груз берёт ось Риффа-партнёра.

### 8.4 Диско-шар (`disco`)

1. **Цвет X:** запомненный при свапе с обычной фишкой (5.1.4), иначе `mf()` в момент `t0` (3.2).
2. **Список L** (`#L` — его длина): обычные фишки цвета X в `idle`, не закреплённые (с проводами тоже), и целые шарики (`balloon`) цвета X; по расстоянию Чебышёва от шара, затем по индексу. Если X нет — L пуст. Все фишки L закрепляются этим источником в `t0` (правило 7.2.7 для шара заменяется этим); шарики не двигаются и не закрепляются.
3. **Шаг k** (с нуля) — в тике `t0 + T.disco_step·k`: если фишка L[k] (по id) всё ещё закреплена этим источником, или шарик L[k] (по id) всё ещё цел, — удар по её клетке, событие `disco_ray`. Иначе шаг пропускается: удара нет, его время не сдвигает следующие шаги.
4. **Своя клетка** — в тике `t0 + T.disco_step·#L` (при пустом L — в `t0`). Этот удар снимает шар.
5. Естественный порядок: шаги по k, затем своя клетка.

Фишка L под проводами при своём шаге теряет слой проводов, как при любом ударе.

### 8.5 Комбо (свап двух спецфишек, центр — клетка `to`)

| | riff | sub | bird | disco |
|---|---|---|---|---|
| **riff** | «Крест» | «Тройной крест» | Пташка несёт Рифф | Цвет X → Риффы |
| **sub** | | «Бас-дроп» | Пташка несёт Сабвуфер | Цвет X → Сабвуферы |
| **bird** | | | «Трио» | Цвет X → Пташки |
| **disco** | | | | «Гранд-финал» |

**Общие правила.**
- Метка комбо — `(a, 1)` свапа. Один комбо-эффект — один источник (`own` — обе спецфишки, `centre` — `to`); груз Пташки и превращённые спецфишки — новые источники с меткой комбо.
- Обе спецфишки стоят `armed` до первого удара комбо по центру; этот удар снимает обе (7.2.4).
- Пути закрепляются по 7.2.7, кроме «Цвет X» (там закрепляет список L).
- Если клетка попадает в геометрию несколько раз — остаётся самое раннее попадание (7.2.6).

**Геометрия и время** (естественный порядок везде — по тику, затем по индексу, если не сказано иное):

| Комбо | Удары | Первый удар по центру |
|---|---|---|
| «Крест» (riff+riff) | как Рифф из центра сразу по двум осям: клетки ряда и колонки центра на расстоянии `d` — в `t0 + R(d)` | `t0` |
| «Тройной крест» (riff+sub) | разряды по рядам y−1, y, y+1 и колонкам x−1, x, x+1. Разряд ряда `y+k` выходит из клетки `(x, y+k)`, разряд колонки `x+k` — из `(x+k, y)`. Клетка на расстоянии `d` от точки выхода вдоль разряда — в `t0 + T.sub_swell + R(d)` | `t0 + T.sub_swell` |
| «Бас-дроп» (sub+sub) | как Сабвуфер, но r = 0..3 (7×7) | `t0 + T.sub_swell` |
| Пташка с грузом (bird+riff, bird+sub) | крест в центре в `t0`, затем выбор цели «С грузом» (раздел 9) и удар с грузом по 8.3 | `t0` |
| «Трио» (bird+bird) | крест в центре в `t0`, затем три цели по разделу 9, выбранные по очереди (резерв и закрепление — как в 8.3). Выбор без кандидатов отменяет этот и все следующие удары (без трат случайности). Удары — записи `bird_impact` источника комбо на `t0 + T.bird_flight` в порядке выбора (в турбо — сразу после выборов). Естественный порядок: крест по индексу, выборы, удары в порядке выбора | `t0` |
| «Гранд-финал» (disco+disco) | пауза, затем каждая существующая клетка поля: клетка на расстоянии Чебышёва `r` от центра — в `t0 + T.finale_pause + T.ring·r`. Источник с флагом `all_layers`: каждый удар бьёт все слои клетки — провода, слот и пол (7.1), как в плане | `t0 + T.finale_pause` |
| «Цвет X → спецфишки» (disco + riff/sub/bird) | см. ниже | `t0 + T.transform_step·#L` |

**«Цвет X → спецфишки».**
1. X = `mf(без проводов)`. L — обычные фишки цвета X в `idle` без проводов, не закреплённые, по расстоянию Чебышёва от центра, затем по индексу (шарики сюда не входят). Все фишки L закрепляются источником комбо в `t0`.
2. Превращение k (с нуля) — в тике `t0 + T.transform_step·k`: если L[k] всё ещё закреплена этим источником, она превращается (id и метка сохраняются) в спецфишку вида партнёра в состоянии `armed`. Риффы получают ось `h` при чётном k и `v` при нечётном. Засчитывается сбор фишки цвета X, +30 очков, событие `transform`. Иначе превращение пропускается, его время сохраняется.
3. В тике `t_end = t0 + T.transform_step·#L` источник комбо бьёт клетку `to` (этот удар снимает обе спецфишки комбо), затем `from` (открытый слот).
4. Пусть `t_last = t0 + T.transform_step·(#L − 1)`. Запуск k — запись `activate` на тик `t_last + T.fire_step·(k+1)`: если превращение k состоялось (фишка L[k] — `armed` спецфишка), она активируется внутри этой записи с меткой комбо; иначе запись ничего не делает.
5. Естественный порядок: превращения по k, удары по `to` и `from`, запуски по k.
6. Превращённые спецфишки стоят `armed` и цепочкой не запускаются (7.2.2).

### 8.6 Цепочки

- Спецфишка в `idle`, получившая удар `effect`, запускается (7.2.1): `armed` сейчас, активация через `T.chain` с меткой ударившего источника, в той клетке, где стоит.
- Рифф сохраняет свою ось (кроме Риффа-груза, 8.3). Диско-шар от цепочки выбирает X при активации.

## 9. Цели Пташки

Цель выбирается в момент выбора (после креста) по текущей доске.

**Уровень клетки** — наибольший из подходящих строк. «Фишка» в таблице — фишка в `idle`, не закреплённая; фишка в другом состоянии ничего не даёт сама, её слот считается открытым. Если в клетке закреплённая фишка, уровень клетки — 0 целиком (её и так ударит другой источник).

| Уровень | Что в клетке |
|---|---|
| 5 | целый `concrete`, пока открыта цель `break concrete` |
| 4 | целый блокер другого вида из открытой цели `break`; обычная фишка без проводов цвета открытой цели `collect`; незажжённая плитка при открытой цели `light`, если этот удар её повредит: проводов нет и либо слот открыт, либо в нём обычная фишка, либо одноклеточный блокер с `hp` 1 |
| 3 | клетка прямо под микрофоном в `idle`, пока открыта цель `deliver`, если удар её освободит: в ней обычная фишка без проводов или одноклеточный блокер с `hp` 1 |
| 2 | любой другой целый блокер; обычная фишка под проводами; спецфишка |
| 1 | любая другая обычная фишка |
| 0 | всё остальное: пустой или открытый слот без плитки уровня 4, микрофон |

- Колонка 2×2 даёт уровень по строкам блокеров только в своей левой верхней клетке; остальные три её клетки — уровень 0. Плитки под колонкой строкой 4 не учитываются: колонка — не одноклеточный блокер.

**Кандидаты** — существующие клетки с уровнем ≥ 1, кроме:
- клеток объектов, уже задетых текущим источником (его ключи дедупликации, включая крест);
- клеток объектов, зарезервированных любой летящей Пташкой.

Если кандидатов нет — «целей нет» (8.3.4).

**Одиночный удар.** Максимальный уровень → максимальная «плотность» (число существующих клеток с уровнем ≥ 3 в квадрате 3×3 с центром в кандидате, сам кандидат включён) → выбор из потока `effects` среди равных лучших (3.2.1: одна трата, даже если лучший один).

**С грузом.** Площадь груза: Сабвуфер — 5×5 с центром в кандидате; Рифф — весь ряд или вся колонка через кандидата. Объект входит в площадь, если в неё попадает хотя бы одна его клетка; колонка входит один раз с уровнем своей левой верхней клетки. Для кандидата считается кортеж `(A, B, C, D)` — число объектов площади с уровнем 4–5, 3, 2 и 1. Побеждает лексикографически наибольший кортеж («больше всего элементов цели», как в плане); у Риффа сначала выбирается лучшая из двух осей (при равенстве `h`), и эта ось используется при ударе. Среди равных лучших — выбор из потока `effects` (одна трата).

**«Трио».** Три цели выбираются по очереди, каждая — с учётом резервов предыдущих; каждый выбор с кандидатами тратит один `next_int`.

## 10. Гравитация, спавн, микрофоны

### 10.1 Назначение падений (шаг 5 тика)

```
counter[x] = 0 для каждой колонки
для y = H..1, для x = 1..W:
  c = (x, y)
  если c существует и её слот пуст:
    r = scan(c)
    piece(Q)  -> перенос Q в c
    spawn     -> новая фишка в c
    wait      -> ничего
    blocked   -> диагональ для c

scan(c):
  k = y_c
  пока k > верх отрезка c:
    k = k - 1
    e = содержимое слота (x, k)
    если e пусто: продолжить
    1. e (фишка или блокер) в clear, swap или armed   -> wait
    2. e закреплена                                   -> wait
    3. e — целый блокер или фишка под проводами          -> blocked
    4. e — подвижная фишка в idle или fall              -> piece(e)
  -- все клетки отрезка над c пусты
  если верх отрезка — спавнер -> spawn, иначе -> blocked
```

**Перенос Q** из клетки S в c: `offy += (y_c − y_S)·3600`, `offx` не меняется; метки по 1.3.5 (с учётом клеток между S и c). Если Q была `idle`: `state = fall`, `vy = T.fall_v0`, `delay = counter[x]`, `counter[x] += 1`. Если Q уже падала — `vy` и `delay` сохраняются, счётчик не растёт. S пустеет и будет обработана позже в этом же проходе.

**Спавн** под спавнером в ряду `y_s`: новая фишка (микрофон по 10.4 или обычная по 10.3) получает новый id и записывается прямо в c в состоянии `fall`: `vy = T.fall_v0`, `delay = counter[x]`, `counter[x] += 1`, `offx = 0`, метка по 1.3.6, событие `spawn`.
- `offy = max((y_c − y_s + 1)·3600, y_c·3600 − top + 3600)`, где `top` — наименьший `vis_y` среди падающих фишек этого отрезка (включая заспавненные раньше в этом проходе); если таких нет — только первый член. То есть фишка стартует на клетку выше спавнера, но не ближе чем на клетку к самой высокой падающей фишке.
- Пока фишка целиком выше верхнего края своего спавнера (`vis_y ≤ (y_s − 1)·3600`), `pieces()` отдаёт её с `hidden = true`; клиент обрезает её рисование по верхнему краю спавнера.

**Диагональ** для клетки c со статусом `blocked`:
1. Если в отрезке c ниже неё есть падающая фишка, чей визуальный центр выше центра c (`vis_y < y_c·3600`), — c в этом проходе считается `wait`.
2. Доноры — клетки `(x−1, y−1)` и `(x+1, y−1)`; в чётных тиках сначала левый, в нечётных — правый. Донор D подходит, если в его клетке подвижная фишка в `idle`, не закреплённая, и клетка под D не существует или её слот не пуст.
3. Первый подходящий D переносится в c: `offx = +3600` (донор слева) или `−3600` (справа), `offy = 3600`, `state = fall`, `vy = T.fall_v0`, `delay = counter[x]`, `counter[x] += 1`; метки по 1.3.5. Фишка, которая в этом же проходе займёт освободившуюся клетку D, получает `vy = min(vy, vy_D)` и `delay = max(delay, delay_D + 1)`.
4. Подходящих доноров нет — c остаётся **дырой**. Дыры допустимы в покое; `has_move`, перемешивание и подсказка их просто пропускают (в них нет фишек). Дыра заполнится, когда исчезнет препятствие.

Назначение — любой перенос, спавн или диагональ. Их число за проход нужно для покоя (раздел 11).

### 10.2 Движение (шаг 6)

Обычный режим:

```
для x = 1..W:
  для каждой фишки P в fall с целевой колонкой x, по убыванию целевого y:
    если P.delay > 0: P.delay -= 1; следующая
    vy = min(vy + T.fall_acc, T.fall_vmax)
    new = offy - vy
    B = ближайшее содержимое ниже целевой клетки P в том же отрезке
        (если B падает, она уже сдвинута в этом тике)
    если B в fall:
      lim = y_P·3600 - vis_y(B) + 3600        -- не ближе клетки к B
      если lim > new:                        -- упёрлась (строго больше)
        new = min(lim, offy)                 -- упор не поднимает фишку
        vy = min(vy, B.vy)
    d = offy - new; offy = new
    если offx ≠ 0: |offx| уменьшается на d, не ниже 0 (знак сохраняется)
    если offy <= 0:
      offy = 0, offx = 0, vy = 0, state = idle, settle_tick = now
      поле «грязное», событие land
```

Турбо: каждая фишка в `fall` (колонки слева направо, в колонке снизу вверх) сразу приземляется: `offy = offx = vy = delay = 0`, `idle`, `settle_tick = now`, поле «грязное», событие `land`.

### 10.3 Цвет новой фишки

Для каждого спавна в порядке прохода 10.1:
1. Решение о микрофоне (10.4). Микрофон — случайность не тратится.
2. Если уровень помощи > 0: `p = int(100)` из потока `spawn`. При `p ≤ 5` (уровень 1: 3–4 поражения подряд на уровне) или `p ≤ 10` (уровень 2: 5 и больше) — принудительный цвет, больше выборов нет.
3. Иначе — взвешенный выбор цвета уровня (3.2) с весами `spawn_weights` из потока `spawn`.

**Принудительный цвет** — первое подходящее:
1. цвет открытой цели `collect` с наибольшим остатком (ничья — меньший номер);
2. при открытой цели `break balloon` — цвет, у которого на поле больше всего целых шариков (ничья — меньший номер);
3. `mf()`;
4. наименьший цвет уровня.

Помощь работает только в пользу игрока, покупки на неё не влияют. Уровень помощи записывается в реплей.

### 10.4 Микрофоны

- **Счётчики:** `released` — выпущено (стартовые считаются), `on_board` — на поле и не доставлены, `moves_made` — принятые свапы и тапы минус откаты (5.1, 5.2; бустеры и `continue` не считаются), `last_mic` — `moves_made` в момент последнего выпуска. На старте `last_mic = 0`, если есть стартовые микрофоны, иначе `−gap_moves`.
- **Выпуск.** Спавн ставит микрофон вместо цветной фишки, если одновременно:
  - есть цель `deliver` и `released < total`;
  - `on_board < on_board_max`;
  - `moves_made − last_mic ≥ gap_moves`;
  - в этом проходе 10.1 микрофон ещё не выпускался.

  Тогда `released += 1`, `on_board += 1`, `last_mic = moves_made`.
- **Доставка** проверяется в шаге 7 **каждого** тика, после поиска матчей: каждый микрофон в `idle` на стойке, по индексу, переходит в `clear` на `T.clear`; `vac` = его метка; `on_board -= 1`; цель `deliver` −1; событие `mic_delivered`.

## 11. Покой и конец хода

**Поле в покое**, если одновременно:
- нет фишек и блокеров в `fall`, `swap`, `clear`, `armed`;
- очередь планировщика пуста (значит, нет закреплённых фишек и резервов Пташек);
- поле не «грязное»;
- в последнем проходе 10.1 не было ни одного назначения.

**Очередь конца хода** — принятые свапы и тапы в порядке `a`, кроме возвращённых; у каждого флаг `noise_hit` и поле `merged` (1.3.10).

**Шаг 8**, если поле в покое, — по состоянию игры:
- `playing`:
  1. **Рост помех.** Сначала для действий очереди по убыванию номера: `credited[a] = noise_hit[a]` или (`merged[a]` стоит в очереди и `credited[merged[a]]`). Затем для каждого действия очереди по возрастанию номера, если `credited` ложно и на поле сейчас есть хотя бы одна помеха:
     - список пар строится заново по текущей доске: (помеха, соседняя по стороне обычная фишка в `idle` без проводов, не в клетке-спавнере), по индексу помехи, затем фишки;
     - пустой список — ничего; иначе одна пара выбирается из потока `effects` (3.2), фишка становится помехой (id и метка сохраняются), событие `noise_spread`.

     Очередь очищается.
  2. Если `moves_left == 0` — состояние `out_of_moves`.
  3. Иначе, если `has_move()` ложно, — перемешивание (12.2).
- `out_of_moves`, `lost`, `complete` — ничего.
- `won_wait` — переход в `concert` (13).
- `concert` — фаза C (13).

После этого `rest_flag` = «поле всё ещё в покое» (5.3).

## 12. Ходы, перемешивание, подсказка

### 12.1 `has_move` и число ходов

- **Пары:** для каждой клетки по индексу — пара с правым соседом, затем с нижним. Пара годится, если в обеих клетках подвижные фишки в `idle`, не закреплённые, и либо участвует спецфишка, либо виртуальный обмен даёт матч через одну из двух клеток (5.1.2).
- `moves()` — список годных пар в этом порядке. **Число ходов** стартовой доски (4.3) — длина этого списка.
- `has_move()` истинно, если есть спецфишка в `idle`, не закреплённая (тап), или список пар не пуст.

### 12.2 Перемешивание (поток `shuffle`; на старте — `init`)

Кандидаты — обычные фишки в `idle` без проводов, не закреплённые, по индексу; `n` — их число, их клетки — клетки перемешивания. Каждая попытка начинается с исходной расстановки и проходит, если на доске нет матча и список пар 12.1 не пуст (тап спецфишки не в счёт: так Ремикс всегда даёт свап).

1. До 50 попыток перестановки: `for i = n, 2, -1 do j = int(i); a[i], a[j] = a[j], a[i] end`. Фишки переезжают с id и метками.
2. Иначе до 50 попыток перекраски: клетки перемешивания по индексу получают цвета по правилу 4.2 с весами `spawn_weights`. Фишки сохраняют id и метки.
3. Иначе исходная расстановка возвращается, и кандидат `int(n)` становится Риффом с осью `h` (при n ≥ 1).
4. Если кандидатов нет: случайная (`int`) обычная фишка под проводами теряет провода (событие `freed`) и становится Риффом `h`.
5. Если нет и таких: случайная помеха поля убирается и заменяется Риффом `h` (id сохраняется, событие `destroy`, очков нет). В цель `break noise` она засчитывается, только если была последней помехой на поле: иначе цель стала бы невыполнимой.
6. Если нет ничего — состояние `out_of_moves` с флагом `stuck` (событие `state` с `reason = stuck`). `continue` в нём отклоняется (`no_candidates`): продолжение не продаётся, когда оно не может помочь; остаются бустеры и `give_up`. Флаг снимается при выходе из `out_of_moves`.

- Каждая фишка, у которой изменились клетка или цвет, и новый Рифф уходят в `swap` без обмена на `T.shuffle` (блокировка: игрок успевает увидеть новую расстановку). В конце блокировки (шаг 2) — `idle`, `settle_tick = now`, поле «грязное».
- Ход не тратится. Событие `shuffle`.
- `remix` (5.3) выполняет пункты 1–3.
- На старте (4.3) перемешивание идёт без блокировки и без события; пункты 4–6 на старте ничего не делают (первый покой повторит перемешивание по правилам игры).

### 12.3 Подсказка `game:hint()`

Чистая функция. Считается по списку `moves()` и тапам по спецфишкам в `idle`, не закреплённым:

| Ярус | Ход | Порядок внутри яруса |
|---|---|---|
| 4 | свап двух спецфишек | ранг комбо: disco+disco, disco+sub, disco+riff, disco+bird, sub+sub, riff+sub, bird+sub, bird+riff, riff+riff, bird+bird |
| 3 | свап, после которого виртуальная группа создаёт спецфишку (6.1); свап Диско-шара с обычной фишкой | ранг лучшей спецфишки (disco > sub > riff > bird; свап Диско-шара — disco), затем больше суммарный размер групп (у свапа Диско-шара — число обычных фишек цвета X в `idle`) |
| 2 | свап с прогрессом цели; свап Риффа, Сабвуфера или Пташки с обычной фишкой или микрофоном; свап Диско-шара с микрофоном; тап по спецфишке | сначала свапы с прогрессом (больше размер групп), затем ходы спецфишкой по рангу sub > riff > bird > disco, свап раньше тапа |
| 1 | любой другой ход | больше размер групп |

- Последний ключ везде — меньший индекс первой клетки пары (у тапа — его клетка).
- **Прогресс цели:** в виртуальной группе есть фишка цвета открытой цели `collect`; или клетка группы на незажжённой плитке при цели `light`; или клетка группы соседствует по стороне с блокером открытой цели `break`, который ломается от `adjacent` (record_box, noise, column, balloon цвета группы); или клетка группы стоит прямо под микрофоном при открытой цели `deliver`.
- Возвращает `{from, to}` (from — клетка с меньшим индексом), `{at}` для тапа или `nil`, если ходов нет. Показ подсказки (5 с бездействия, покачивание) — забота клиента.

## 13. Победа, финальный концерт, поражение

1. **`won_wait`.** Игра переходит сюда в момент выполнения последней цели (событие `state` сразу после события `goal`). Ввод закрыт, кроме `skip`. Каскады и свапы в полёте доигрываются, включая откаты с возвратом хода.
2. **Переход в `concert`** — в шаге 8 первого тика покоя в `won_wait`, тик `tc = now`:
   - `moves_at_win = moves_left`; `n = moves_left`; `A = act`; `rounds = 0`; очередь конца хода очищается;
   - ставятся записи фазы A `concert_a`: `k = 1..n` на `tc + T.concert_step·k`;
   - ставится запись начала фазы B `concert_b` на `tc + T.concert_step·n + T.fire_step`.

   (Записи из шага 8 с тиком ≤ `now` выполняются в шаге 3 следующего тика, 15.1.)
3. **Фаза A, шаг k:** `moves_left -= 1` (событие `moves`). Одна обычная фишка в `idle` без проводов, не закреплённая (поток `effects`), становится Риффом (id сохраняется) с осью `h` при нечётном k и `v` при чётном, с меткой `(A+1, 0)`; +300 очков; событие `concert_riff`. Если кандидатов нет — Риффа нет.
4. **Фаза B** (тик `t_B` записи начала): `rounds += 1`; S — все спецфишки в `idle`, не закреплённые, по индексу. Все они сразу переходят в `armed`; активация `S[i]` (с нуля) — запись `activate` на тик `t_B + T.fire_step·i` с меткой `(A+1, 1)`.
5. **Фаза C** — в шаге 8 каждого тика покоя в `concert`: если есть спецфишка в `idle` и `rounds < 20` — запись начала фазы B на `now + T.fire_step`; иначе состояние `complete`.

**Итог уровня:** очки, `moves_at_win` (мета платит +5 монет за каждый), звёзды по сложности (`easy` и `medium` — 1, `hard` — 2, `super_hard` — 3), список `unplaced` (17.3).

- **`out_of_moves`**: клиент предлагает продолжение (`continue`, кроме флага `stuck`), бустеры или сдачу (`give_up` → `lost`).
- **`skip`**: включает турбо до `complete` (решение архитектора). Итог может отличаться очками от просмотренного концерта — это допустимо и записывается в реплей.

## 15. Тик

```
step():
  tick += 1; now = tick
  1. (команды окна now уже применены, 5.0)
  2. таймеры swap / swap_fail / swap_back (в порядке запуска), затем блокировки,
     истекающие в now; если хоть один истёк: поиск и разрешение матчей (6, с 6.2.1),
     откаты (5.1.3)
  3. очередь: все записи с due <= now в порядке (due, seq),
     включая поставленные во время шага 3
  4. фишки и блокеры в clear с истёкшим таймером исчезают
  5. назначение падений и спавн (10.1)
  6. движение падающих (10.2)
  7. если поле «грязное»: поиск и разрешение матчей (6);
     затем доставка микрофонов (10.4) — в каждом тике
  8. если поле в покое: раздел 11 (и 13); обновить rest_flag
```

### 15.1 Время и планировщик

1. `now` — номер выполняемого тика. Команда, применённая между тиками N и N+1, имеет `now = N+1` (этот тик пишется в реплей).
2. Команды никогда не наносят ударов: они проверяют условия, меняют состояния, счётчики и ставят записи на `now`. Тап ставит активацию, бустер — своё действие.
3. Длительность D, начатая в `now`, истекает в тике `now + D` в шаге-владельце: таймеры свапов и блокировок — шаг 2; `clear` — шаг 4; записи — шаг 3. Пример: свап, принятый перед тиком N+1, заканчивается в шаге 2 тика N+11; фишка, уничтоженная в шаге 7 тика t, исчезает в шаге 4 тика t+9.
4. **Очередь** — записи из простых данных `{due, seq, kind, data}` (15.2), упорядоченные по `(due, seq)`. `seq` — счётчик постановок: новая запись получает `seq + 1`, и счётчик растёт. Замыканий в записях нет.
5. Запись с `due ≤ now`, поставленная командой, в шаге 2 или во время шага 3, выполняется в шаге 3 тика `now` (во время шага 3 — дописывается в текущий проход). Запись с `due ≤ now`, поставленная в шагах 4–8, получает `due = now + 1`.
6. `t0` активации — тик, в шаге 3 которого выполняется её запись. Действия эффекта с тиком `t0` выполняются сразу внутри записи активации (7.2.6).
7. Защита от зацикливания: больше 100 000 записей за один тик — ошибка ядра (баг). Результат никогда не обрезается молча.
8. **Переключение в турбо** (`skip`, `set_timing` у клона) происходит между тиками, при `now = N+1`:
   - каждый таймер: срок = min(срок, `now` + турбо-значение своего вида);
   - каждая запись: `due = min(due, now)`; затем записи получают `seq = 1..k` в прежнем порядке `(due, seq)`, и счётчик `seq` становится равен `k`;
   - у падающих фишек `delay = 0`; они приземлятся в ближайшем шаге 6;
   - все новые длительности — турбо.

### 15.2 Записи очереди

Одна запись — одно действие. Поля данных всегда пишутся в указанном порядке; отсутствующее значение — 0.

| Код | `kind` | Данные | Кто ставит | Что делает |
|---|---|---|---|---|
| 1 | `activate` | id фишки, клетка, клетка партнёра (0 — не комбо), mv, wv, X (0 — выбрать при активации) | свап 5.1.4, тап 5.2, цепочка 7.2.1, запуски «Цвет X» 8.5, фаза B 13 | если фишки с этим id нет или она не `armed` спецфишка — ничего; иначе активация (раздел 8) |
| 2 | `hit` | id источника, клетка | эффекты и прожекторы | удар |
| 3 | `disco_step` | id источника, k, id объекта L[k] | 8.4 | шаг k |
| 4 | `transform` | id источника, k, id фишки L[k] | 8.5 | превращение k |
| 5 | `bird_impact` | id источника, клетка, груз (0 / 1 riff / 2 sub), ось груза | 8.3, 8.5 | удар Пташки или активация груза |
| 6 | `concert_a` | k | 13 | шаг фазы A |

## 16. События для клиента

Ядро копит события, клиент забирает их вызовом `game:drain_events()`. У каждого события есть поле `t` (тик) и `type`. Координаты — 1-базовые `x, y`; «нет» — поле отсутствует. Позиции объектов клиент читает из `game:pieces()` каждый кадр (17.3).

| type | Поля | Когда |
|---|---|---|
| `swap`, `swap_fail` | `a`, `b` (клетки `from`, `to`), `ids` (id фишек в `a` и `b`), `duration` | принятие свапа / неудачного свапа |
| `swap_back` | те же (`a` — `from` исходного свапа) | откат |
| `moves` | `left` | каждое изменение `moves_left` |
| `match` | `cells` (клетки по индексу), `color`, `wave` (W), `act` (M), `special` (вид или нет) | начало разрешения группы |
| `clear` | `id`, `x`, `y`, `kind`, `color`, `special`, `cause` (`match` \| `effect` \| `fired`) | уничтожение обычной фишки (включая фишку в клетке новой спецфишки); снятие сработавшей спецфишки |
| `special_new` | `id`, `x`, `y`, `special`, `axis` | новая спецфишка группы |
| `activate` | `id` (нет у груза), `x`, `y`, `special`, `axis`, `color` (X Диско-шара), `combo` (`cross`, `triple_cross`, `bass_drop`, `bird_riff`, `bird_sub`, `trio`, `finale`, `color_riff`, `color_sub`, `color_bird` или нет), `partner` (id второй спецфишки комбо) | первым событием активации |
| `bolt` | `x`, `y` (точка выхода), `dir` (`l`/`r`/`u`/`d`), `at` (тик выхода) | при активации, по каждому разряду Риффа, «Креста», «Тройного креста», прожектора — даже если в направлении нет клеток |
| `ring` | `x`, `y`, `r`, `at` | при активации: Сабвуфер r = 0..2, «Бас-дроп» 0..3, «Гранд-финал» 0..наибольшее кольцо с существующей клеткой |
| `bird_fly` | `x`, `y`, `tx`, `ty`, `carry` (`riff`/`sub` или нет), `axis`, `duration` | после выбора цели; нет цели — нет события |
| `disco_ray` | `x`, `y`, `tx`, `ty` | выполненный шаг Диско-шара |
| `transform` | `id`, `x`, `y`, `special`, `axis` | выполненное превращение |
| `hit` | `x`, `y`, `layer` (`wires`/`blocker`/`floor`), `item` (вид блокера), `hp` (остаток) | урон проводам; урон блокеру без разрушения; каждый урон полу |
| `destroy` | `id`, `x`, `y`, `item` | разрушение блокера; помеха, убранная 12.2.5 |
| `floor_lit` | `x`, `y` | сразу после `hit` пола с остатком 0 |
| `freed` | `id`, `x`, `y` | сняты последние провода (удар или 12.2.4) |
| `score` | `delta`, `total`, `x`, `y` | одно на удар, давший очки (сумма по всем слоям, клетка удара); бонус группы (клетка новой спецфишки); превращение; Рифф концерта |
| `goal` | `index` (номер цели с 1), `left` (остаток ≥ 0) | уменьшение остатка; после 0 событий этой цели нет |
| `land` | `id`, `x`, `y` | приземление |
| `spawn` | `id`, `x`, `y`, `kind`, `color` | спавн |
| `praise` | `act`, `wave`, `word` | правило ниже |
| `noise_spread` | `fx`, `fy` (помеха), `x`, `y`, `id` (фишка, ставшая помехой) | рост помех |
| `mic_delivered` | `id`, `x`, `y` | доставка |
| `shuffle` | `moves` ({id, fx, fy, x, y}), `recolors` ({id, color}), `riff` ({id, x, y, from: `piece`/`wires`/`noise`} или нет), `duration` | перемешивание и Ремикс (не на старте) |
| `concert_riff` | `id`, `x`, `y`, `axis` | фаза A |
| `continue_riff` | `id`, `x`, `y` | Рифф продолжения |
| `booster` | `booster`, `at` \| `row` \| `col`, `ok` | начало выполнения бустера (шаг 3); `ok = false` — Ремикс ничего не сделал |
| `state` | `state` (`playing`, `won_wait`, `concert`, `out_of_moves`, `lost`, `complete`), `reason` (`stuck` у `out_of_moves` из 12.2.6) | каждое изменение состояния игры |

**Похвала.** Для каждого действия `m` хранится `praise_best[m]` (сначала 0). Когда разрешается группа с меткой `(M, W)`, берётся наибольший порог `p ∈ {3, 5, 7, 9, 12}` с `p ≤ W`. Если `p > praise_best[M]` — событие `praise {act = M, wave = W, word}` со словом `juicy`, `hit`, `drive`, `vibe`, `legend` для порогов 3, 5, 7, 9, 12, и `praise_best[M] = p`. Так каждое слово звучит не больше раза на действие, при скачке волны звучит только старшее слово, а `legend` — один раз. В концерте `M = A + 1`.

**Порядок событий** — причинный:
- команда: `swap` | `swap_fail` → `moves` → `state`;
- удар: снятие своей спецфишки (`clear` с `fired`) → провода (`hit` → `freed`) → слот (`clear` | `hit` | `destroy`) → пол (`hit` → `floor_lit`) → `score` → `goal` (по номеру цели) → `state`;
- группа: `match` → удары `match` по клеткам → `special_new` → `score` бонуса → удары `adjacent` → `praise`;
- активация: `activate` → `bolt` | `ring` → действия тика `t0` в естественном порядке; у Пташки — крест → `bird_fly`;
- превращение: `transform` → `score` → `goal`; фаза A: `moves` → `concert_riff` → `score`;
- откат: `swap_back` → `moves`;
- событие `state` идёт сразу за событием, которое его вызвало.

## 17. Реплей, хеш, API

### 17.1 Реплей

- **Заголовок:** `core_version`; уровень `{id, version, hash}` (свёртка 17.2 по байтам канонической формы 2.2); `seed` (главный), `attempt`, `salt`; бустеры перед уровнем (упорядоченный список); уровень помощи (0–2); режим таймингов на старте; `input_lock`; `final_tick`; `final_hash`.
- **Команды:** список `{tick, cmd}` принятых команд в порядке применения (неудачный свап тоже записывается).
- **Воспроизведение** применяет команды в их тиках и идёт до `final_tick`; события и хеш обязаны совпасть.
- Золотые реплеи в `tests/golden/` проверяются на каждом прогоне тестов. Отдельный золотой тест — первые 5 выходов каждого потока при `seed = 1`.

### 17.2 Хеш состояния

- **Свёртка:** `h = 0`; для каждого значения `v`: `v = v % 4294967296`; `h = (h*65599 + v + 1) % 2147483629`. Все значения — целые; булевы — 0/1; отсутствие — 0. `tostring` и `string.format` в хеше запрещены.
- **Коды перечислений:**

  | Перечисление | Коды |
  |---|---|
  | вид содержимого | 0 нет, 1 regular, 2 special, 3 mic, 4 blocker |
  | цвет | 0 нет, 1–6 (раздел 0) |
  | спецфишка | 0 нет, 1 riff, 2 sub, 3 bird, 4 disco |
  | ось | 0 нет, 1 h, 2 v |
  | блокер | 0 нет, 1 record_box, 2 concrete, 3 noise, 4 balloon, 5 column |
  | состояние | 1 idle, 2 fall, 3 swap, 4 clear, 5 armed |
  | таймер | 0 нет, 1 swap, 2 swap_fail, 3 swap_back, 4 блокировка, 5 clear |
  | вид источника | 1 match, 2 adjacent, 3 effect |
  | предмет (бустеры, `unplaced`) | 1 stick, 2 row_light, 3 col_light, 4 remix, 5 Рифф перед уровнем, 6 Сабвуфер перед уровнем, 7 Диско-шар перед уровнем, 8 Рифф продолжения |
  | состояние игры | 1 playing, 2 won_wait, 3 concert, 4 out_of_moves, 5 lost, 6 complete |
  | тайминги | 1 normal, 2 turbo |
  | вид записи | 15.2 |

- **Правила раскладки.** Каждое поле пишется всегда (отсутствующее — 0); каждый список предваряется своей длиной; клетки — индексом `i`. Колонка 2×2 пишется в каждой из своих 4 клеток одинаково.
- **Порядок значений:**
  1. по клеткам `i = 1..W·H`:
     - существует, спавнер, стойка, `hp` пола, `hp` проводов, `vac` (mv, wv);
     - содержимое слота (17 полей): вид, цвет (обычной фишки или шарика), спецфишка, ось, блокер, `hp` блокера, состояние, id, метка (mv, wv), `offx`, `offy`, `vy`, `delay`, `settle_tick`, вид таймера, срок таймера;
     - отметки `pins`: длина, id по возрастанию;
  2. счётчики: `tick`, `act`, `seq`, `next_piece_id`, `next_source_id`, `moves_left`, `moves_made`, очки, остатки целей (длина, по порядку), `released`, `on_board`, `last_mic`, состояние игры, `stuck`, режим таймингов, `input_lock`, `rest_flag`, «грязный» флаг, число назначений последнего прохода, `tc`, `rounds`, `moves_at_win`;
  3. свапы в полёте (таймеры `swap`, `swap_fail`, `swap_back`) в порядке запуска: вид таймера, `a` (у неудачного — 0), `from`, `to`, запомненные метки (4 числа; у неудачного — 0), срок. Блокировки перемешивания здесь не пишутся — только в своих клетках;
  4. записи очереди в порядке `(due, seq)`: due, seq, код вида, поля данных (15.2);
  5. активные источники по возрастанию id: id, вид, метка (mv, wv), цвет, `all_layers`, `own` (длина, id), `centre`, ключи дедупликации (длина, по возрастанию), резервы (длина, клетки по возрастанию);
  6. очередь конца хода: `a`, `noise_hit`, `merged`;
  7. похвалы: пары (`m`, `praise_best[m]`) с ненулевым значением, по возрастанию `m`;
  8. `unplaced`: коды предметов по порядку;
  9. 4 потока × 6 слов состояния генератора.

| `game:replay()` | 17.1 |

- Запросы (`can_swap`, `has_move`, `moves`, `hint`, `is_stable`, `pieces`, `cells`, `status`, `result`, `hash`, `replay`) чистые: не тратят случайность, не меняют состояние и события.
- `game:clone(opts)` — независимая глубокая копия с пустым буфером событий.
- `opts.reseed = k` — потоки `spawn`, `effects` и `shuffle` клона инициализируются заново (3.1) сидом, свёрнутым из (`seed`, `act`, `k`) той же формулой, что сид попытки. Просмотр ходов ботами идёт только на таких клонах: будущие цвета и выборы настоящей игры ботам недоступны.
- `clone:set_timing('turbo')` — переключение по 15.1.8.
- `game:run_to_rest(max_ticks = 20000)` — вызывает `step()`, пока `is_stable()` ложно, и возвращает число сделанных тиков (0, если поле уже в покое); превышение лимита — ошибка.
