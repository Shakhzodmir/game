# Правила доски GLOW — точная спецификация ядра (v2)

Этот документ — контракт для ядра `core/` (чистый Lua), ботов и клиента. Здесь нет «примерно»: любая ситуация на доске должна однозначно следовать из правил ниже. Если код и документ расходятся, это баг одного из них; исправление фиксируется в обоих. Имена и id — по глоссарию из `decisions.md`.

---

## 0. Основы

- **Тик.** Симуляция идёт фиксированными тиками, 60 в секунду. Всё время в ядре измеряется в тиках.
- **Единицы.** 1 клетка = 3600 единиц. Все координаты, смещения и скорости — целые числа.
- **Координаты API.** `x` — колонка, 1..W слева направо; `y` — ряд, 1..H сверху вниз. Индекс клетки `i = (y-1)*W + x`. В JSON уровня координаты считаются с нуля (раздел 2), загрузчик переводит их в 1-базовые.
- **Порядок обхода.** Везде, где порядок влияет на результат, обход идёт по возрастанию индекса клетки, если не сказано иное. `pairs()` для таких мест запрещён.
- **Цвета.** Глобальный порядок: `red`=1, `orange`=2, `yellow`=3, `green`=4, `blue`=5, `purple`=6. Ничьи между цветами решаются в пользу меньшего номера.
- **Детерминизм.** Результат однозначно определяется уровнем, сидами, режимом таймингов и списком команд с номерами тиков.

## 1. Модель поля

Клетка существует или нет (пустота `.`). У существующей клетки три слоя:

| Слой | Что хранит |
|---|---|
| Пол (`floor`) | Танцпол: прочность `hp` 1–2. Плитка «зажигается», когда `hp` падает до 0 |
| Слот (`slot`) | Одна фишка (piece) или ничего |
| Покрытие (`overlay`) | Провода: прочность 1–2, только поверх обычной фишки |

Статические свойства клетки: `spawner` (сюда сверху входят новые фишки), `exit` (стойка микрофона).

### 1.1 Виды фишек (`kind`)

| kind | Примеры | Падает | Свапается | Матчится | Удар по ней |
|---|---|---|---|---|---|
| `regular` | 6 цветов | да | да | да | уничтожается (кроме удара `adjacent`) |
| `special` | riff, sub, bird, disco | да | да | нет | взводится (раздел 7) |
| `mic` | микрофон | да | да | нет | не действует |
| `blocker` | record_box, concrete, noise, balloon, column | нет | нет | нет | по таблице раздела 7.3 |

Фишка под проводами (`fixed`) не падает, не свапается, но матчится на месте.

### 1.2 Состояния фишки (`state`)

| state | Значение | Матчится | Ввод | Бьётся ударом |
|---|---|---|---|---|
| `idle` | покой | да (regular) | да | да |
| `fall` | летит в свою целевую клетку (по вертикали или диагонали) | нет | нет | нет (клетка «открыта») |
| `swap` | участвует в свапе или откате | нет | нет | нет (клетка «открыта») |
| `clear` | уничтожается, через `T.clear` тиков исчезнет | нет | нет | нет (клетка «открыта») |
| `armed` | спецфишка взведена и ждёт срабатывания; висит на месте | нет | нет | нет (клетка «открыта») |

Статические блокеры всегда `idle`. Фишка в состоянии `fall` уже записана в свою **целевую** клетку, а отставание до неё хранится смещением `offy` (и `offx` при диагонали) в единицах. Визуальная позиция = центр целевой клетки минус смещение.

### 1.3 Метки хода и волны

- Каждое действие игрока (свап, тап, бустер) получает номер действия `act` = 1, 2, 3…
- У каждой фишки есть метка `(mv, wv)` — действие и волна, которые её «сдвинули» последними. Начальная метка — `(0, 0)`.
- У каждой клетки есть метка освобождения `vac = (mv, wv)`: чем она была опустошена.
- Метки сравниваются лексикографически: сначала `mv`, потом `wv`.

Правила меток:
1. Обе фишки принятого свапа получают метку `(act, 0)`.
2. Когда удар источника с меткой `(m, w)` уничтожает содержимое клетки, клетка получает `vac = (m, w)`.
3. Когда гравитация переносит фишку `P` из клетки `S` в клетку `T`: `P.метка = max(P.метка, T.vac)`, затем `S.vac = P.метка`.
4. Новая фишка из спавнера получает `T.vac` целевой клетки.
5. Метка группы (раздел 6): `M = max mv` по фишкам группы; `W = 1 + max wv` по фишкам группы с `mv == M`.
6. Эффект спецфишки несёт метку того, что её запустило: группы, свапа `(act, 1)`, тапа `(act, 1)` или удара, который её взвёл.

Волна `W` определяет очки (`20 × W` за фишку), высоту ноты (ступень `min(W-1, 10)` пентатоники) и похвалы (раздел 16).

## 2. Формат уровня (JSON)

```json
{
  "id": 42, "version": 1,
  "size": [9, 9],
  "moves": 28,
  "difficulty": "hard",
  "colors": ["red", "orange", "yellow", "blue", "purple"],
  "goals": [
    {"type": "collect", "color": "red", "count": 30},
    {"type": "break", "item": "record_box", "count": 18},
    {"type": "light"},
    {"type": "deliver", "count": 3}
  ],
  "cells": ["..#####..", ".#######.", "#########", "..."],
  "spawners": "top",
  "exits": "bottom",
  "floor":   [{"at": [3, 4], "hp": 2}],
  "overlay": [{"at": [2, 6], "type": "wires", "hp": 1}],
  "slots":   [
    {"at": [4, 4], "type": "record_box", "hp": 3},
    {"at": [0, 5], "type": "concrete", "hp": 2},
    {"at": [1, 1], "type": "noise"},
    {"at": [6, 2], "type": "balloon", "color": "red"},
    {"at": [3, 7], "type": "column", "hp": 8},
    {"at": [4, 0], "type": "riff", "axis": "h"},
    {"at": [5, 0], "type": "piece", "color": "blue"},
    {"at": [2, 0], "type": "mic"}
  ],
  "mic": {"total": 3, "on_board_max": 2, "gap_moves": 3},
  "spawn_weights": null
}
```

- `size` = `[W, H]`, где 5 ≤ W ≤ 9 и 5 ≤ H ≤ 11. `cells` — H строк по W символов: `#` — клетка, `.` — пустота.
- `at` = `[x, y]` с нуля: x — колонка слева направо, y — ряд сверху вниз.
- `difficulty`: `easy` | `medium` | `hard` | `super_hard`.
- `colors`: от 4 до 6 разных цветов.
- `moves`: от 5 до 60.
- `spawners`: `"top"` — в каждой колонке самая верхняя существующая клетка; либо список `[[x, y], …]`. Над спавнером не должно быть существующей клетки.
- `exits`: `"bottom"` — в каждой колонке самая нижняя существующая клетка; либо список. Нужны только для цели `deliver`.
- `column` задаётся левой верхней клеткой и занимает 2×2.
- `mic` нужен только при цели `deliver`. `total` — сколько микрофонов всего появится за уровень, включая стоящие на старте; должно быть `total == count`.
- `spawn_weights`: `null` — все цвета уровня равновероятны; иначе объект `{"red": 3, …}` с целыми весами.

### 2.1 Валидация (ошибка — уровень не загружается)
1. Размеры, символы и длины строк `cells` корректны.
2. Все `at` указывают на существующие клетки. В одном слое у клетки не больше одного элемента. `column` занимает 4 существующие свободные клетки.
3. Провода стоят только над клеткой, где будет обычная фишка: над случайной или над `piece`.
4. Цвета `balloon` и `piece` входят в `colors`.
5. Цели: от 1 до 3 штук.
   - `collect.color` ∈ `colors`;
   - `break.item` ∈ {record_box, concrete, noise, balloon, column}, и `count` ≤ числу таких элементов на старте;
   - `light` — на уровне есть хотя бы одна плитка танцпола;
   - `deliver` — есть блок `mic` и хотя бы одна стойка.
6. Разных элементов не больше трёх. Считаются: record_box, dancefloor, wires, mic, concrete, noise, balloon, column.
7. **Заполнимость.** Если убрать все подвижные фишки и дать гравитации работать в турбо-режиме (статические блокеры и провода остаются), все свободные клетки заполнятся.
8. Стартовая доска генерируется (раздел 4).

## 3. Случайность

- Генератор **MRG32k3a** (L'Ecuyer). Вся арифметика точна в double: все произведения меньше 2^53.
- Отдельные потоки: `init` (стартовая доска, бустеры перед уровнем, Рифф из продолжения), `spawn` (цвета новых фишек и помощь застрявшим), `effects` (цели Пташки, рост помех, выбор фишек для финального концерта), `shuffle` (перемешивание и Ремикс).
- **Сид попытки** = `hash(level_id, attempt, salt)` — целое в [1, 2^31−2]. `salt` — случайное число игрока, создаётся один раз при установке.
- **Инициализация потока** `k` (init=1, spawn=2, effects=3, shuffle=4):
  1. `x = (seed*7 + k*104729 + 12345) mod 2147483647`; если `x == 0`, то `x = 1`.
  2. Шесть раз: `x = x*48271 mod 2147483647`, результат — очередной элемент состояния s1..s6.
  3. Первые 8 выходов отбрасываются.
- `next_int()` возвращает целое в [0, m1−1]. `int(n)` = `next_int() mod n + 1`. Взвешенный выбор: `r = next_int() mod сумма_весов`, затем проход по весам.

## 4. Стартовая доска

1. Из файла уровня ставятся фиксированные элементы: пол, слоты, покрытия.
2. Остальные существующие свободные клетки заполняются по возрастанию индекса обычными фишками из потока `init` по весам `spawn_weights`. Цвет отбрасывается, если он даёт тройку с двумя соседями слева или сверху либо квадрат 2×2 с левым, верхним и левым-верхним соседом. Перебираются разрешённые цвета; если подходящих нет, берётся любой.
3. Проверка: на поле нет ни одного матча и есть **не меньше 3 разных ходов** (`has_move` считает ходы; раздел 12). Если проверка не прошла — повтор с шага 2, до 100 попыток. Потом — перемешивание по разделу 12.
4. Бустеры перед уровнем (Рифф, Сабвуфер, Диско-шар) ставятся по одному на случайную клетку из потока `init`. Кандидаты — клетки с обычной фишкой без проводов, не на плитке танцпола и не цвета из цели `collect`. Если таких нет — любая обычная фишка без проводов. Фишка заменяется спецфишкой; у Риффа ось `h`, если по порядку это первый, третий или пятый Рифф, иначе `v`.
5. Все фишки `idle`, поле в покое.

## 5. Ввод и действия

Команды применяются сразу при вызове `game:input(cmd)`, между тиками. В реплей записывается пара (номер следующего тика, команда). Команды принимаются только в состоянии игры `playing`, кроме `continue`, `give_up` и `skip`.

### 5.1 Свап `{type="swap", from={x,y}, to={x,y}}`
`from` — клетка, которую тянул игрок, `to` — соседняя по стороне клетка.

**Условия принятия** (иначе отказ без изменений):
- осталось больше 0 ходов;
- обе клетки существуют, в обеих фишки `idle` без проводов, вид фишек — regular, special или mic;
- не два микрофона и не две обычные фишки одного цвета.

**Оценка при принятии:**
- если участвует спецфишка — свап валиден;
- иначе виртуальный свап должен дать матч через `from` или `to` среди `idle` фишек (линия ≥3 или квадрат 2×2);
- **нет матча** — «неудачный свап»: обе фишки в `swap` на `T.swap_fail` тиков без обмена, потом снова `idle`. Ход не тратится. Событие `swap_fail`.

**Принятый свап:**
- новое действие `act`, `moves_left -= 1`;
- обе фишки в `swap` на `T.swap` тиков, событие `swap`.

**В тике окончания свапа** фишки меняются клетками, получают метку `(act, 0)` и становятся `idle`, затем:
- **две спецфишки** — комбо (раздел 8.5) в клетке `to`. Обе спецфишки снимаются с поля в этом тике;
- **спецфишка + другая фишка** — спецфишка срабатывает в своей новой клетке. Диско-шар со свапа с обычной фишкой цвета X бьёт по цвету X; со свапа с микрофоном — по самому частому цвету. Клетка второй фишки помечается для поиска матчей;
- **без спецфишек** — если сейчас есть матч через `from` или `to`, клетки помечаются для поиска матчей (разрешатся в этом же тике). Если матча больше нет (соседей за время свапа снесло), фишки снова уходят в `swap` на `T.swap` тиков и возвращаются, ход возвращается (`moves_left += 1`), действие помечается «возвращённым», событие `swap_back`.

### 5.2 Тап `{type="tap", at={x,y}}`
Условие: в клетке `idle` спецфишка и осталось больше 0 ходов. Новое действие, `moves_left -= 1`, спецфишка срабатывает на месте в этом же моменте с меткой `(act, 1)`. Диско-шар от тапа бьёт по самому частому цвету.

### 5.3 Бустеры в уровне `{type="booster", booster=..., at={x,y}|row=y|col=x}`
Разрешены только когда поле в покое (раздел 11). Ход не тратят: создают действие для меток, но не ставят его в очередь конца хода.
- `stick` — один удар типа `effect` по выбранной клетке.
- `row_light` — удары `effect` по всем клеткам ряда слева направо, по одной клетке за `T.light_step` тиков, один источник.
- `col_light` — то же по колонке сверху вниз.
- `remix` — перемешивание по разделу 12 (как автоматическое, но по команде).

### 5.4 Служебные команды
- `continue {moves=n, riff=bool}` — только в состоянии `out_of_moves`: `moves_left += n`; если `riff`, одна обычная фишка без проводов становится Риффом (поток `init`, ось `h`). Игра возвращается в `playing`.
- `give_up` — из `out_of_moves` в `lost`.
- `skip` — в состояниях `won_wait` и `concert`: переключает тайминги в турбо до конца уровня.

## 6. Матчи

**Когда искать.** В конце тика (шаг 7), если поле помечено «грязным»: фишка приземлилась, закончился свап или откат, прошло перемешивание, освободилась фишка из проводов. Поиск идёт **по всему полю** среди `regular` фишек в `idle` (включая фишки под проводами).

**Инвариант:** после шага 7 среди фишек в `idle` нет ни одного матча.

**Группа.** Линии ≥3 одного цвета по горизонтали и вертикали плюс все квадраты 2×2 одного цвета. Линии и квадраты с общими клетками сливаются в одну группу (union-find). Группы обрабатываются по возрастанию наименьшего индекса своих клеток.

### 6.1 Классификация (сверху вниз, первое совпадение)

| Условие | Спецфишка |
|---|---|
| есть линия ≥5 | `disco` |
| есть горизонтальная линия ≥3 и вертикальная линия ≥3 | `sub` |
| есть линия ровно 4 | `riff`, ось = ось этой линии |
| есть квадрат 2×2 | `bird` |
| иначе | нет |

### 6.2 Клетка для спецфишки
Кандидаты — клетки группы **без проводов**. Первое подходящее правило:
1. Клетка группы, которая была `from` или `to` свапа, закончившегося в этом тике.
2. Для `sub` — пересечение горизонтальной и вертикальной линий. Если пересечений несколько, выбор по правилу 3 среди них.
3. Клетка с наибольшим тиком приземления фишки; при равенстве — ниже (больше y), затем левее (меньше x).

### 6.3 Разрешение группы (метка `(M, W)`, новый источник `match`)
1. Событие `match`: клетки, цвет, волна, действие, будущая спецфишка.
2. Каждая клетка группы получает удар `match` (раздел 7). Фишка в клетке спецфишки уничтожается (пол получает урон), и на её место сразу ставится новая спецфишка в `idle` с меткой `(M, W)`.
3. Удары `adjacent`, **один раз на группу**: по каждой клетке вне группы, соседней по стороне хотя бы с одной клеткой группы. Для колонки 2×2 — один удар на объект.
4. Очки: `20 × W` за каждую клетку группы плюс бонус за спецфишку: riff и bird — 60, sub — 90, disco — 150.

## 7. Удары

Удар — `hit(клетка, источник)`. У источника есть id, вид (`match`, `adjacent` или `effect`) и метка `(m, w)`.

**Дедупликация.** Источник бьёт клетку не больше одного раза, а объект 2×2 — не больше одного раза, даже если задел несколько его клеток.

### 7.1 Порядок обработки удара
1. **Провода.** Если на клетке провода: удар `adjacent` ничего не делает. Иначе `hp` проводов уменьшается на 1; при 0 провода снимаются, фишка освобождается (событие `freed`, поле «грязное»). Дальше удар не идёт: фишка и пол защищены.
2. **Слот.**
   - пусто, либо фишка в `fall`/`swap`/`clear`/`armed` — слот «открыт»;
   - `regular`: `adjacent` — ничего; `match` или `effect` — фишка уничтожается;
   - `special` в `idle`: `effect` взводит её (`armed`), срабатывание через `T.chain` тиков с меткой источника; `match` и `adjacent` — ничего;
   - `mic`: ничего, защищает пол;
   - `blocker` — по таблице 7.3.
3. **Пол.** Плитка танцпола с `hp` > 0 получает −1, если:
   - на шаге 2 уничтожено содержимое слота (фишка или блокер), при любом виде удара; **или**
   - удар `effect`, а слот «открыт».
   
   Урон полу — не больше одного за удар. При `hp == 0` — событие `floor_lit`.

**Уничтожение** фишки или блокера: состояние `clear` на `T.clear` тиков, затем клетка пустеет. Сразу при уничтожении засчитываются цели, начисляются очки (удар `effect` по обычной фишке — 30, по слою блокера — 50) и клетке ставится метка `vac`.

### 7.2 Спецфишка при срабатывании
Спецфишка снимается с клетки без урона полу. Её эффект всегда включает удар по собственной клетке, и этот удар бьёт пол как по «открытому» слоту.

### 7.3 Блокеры

| Блокер | hp | Ломается от | Особенности |
|---|---|---|---|
| `record_box` | 1–3 | `adjacent`, `effect` | −1 за удар |
| `concrete` | 1–2 | только `effect` | Учит копить спецфишки |
| `noise` | 1 | `adjacent`, `effect` | Удар отмечает `noise_hit` у действия с меткой `m`. Растёт в конце хода (раздел 11) |
| `balloon` | 1 | `adjacent` группы своего цвета, `effect` | У шарика есть цвет |
| `column` (2×2) | 6–12 | `adjacent`, `effect` | Один удар на источник; при 0 освобождаются все 4 клетки, каждая бьёт свой пол |

Любой урон блокеру даёт событие `hit` с остатком `hp`, уничтожение — событие `destroy`.

## 8. Спецфишки и комбо

Время `t0` — тик срабатывания. У каждого эффекта свой источник вида `effect` с меткой запуска.

### 8.1 Рифф (`riff`, ось h или v)
- `t0`: удар по своей клетке.
- Два разряда летят в обе стороны вдоль оси. Клетка на расстоянии `d` бьётся в тике `t0 + ceil(d·15/7)` (это 28 клеток в секунду).
- Разряды пролетают сквозь пустоты и заканчиваются у края поля.

### 8.2 Сабвуфер (`sub`)
- `t0`: «набухание» `T.sub_swell` тиков.
- Кольцо `r` (расстояние Чебышёва r = 0..2, квадрат 5×5) бьётся в тике `t0 + T.sub_swell + T.ring·r`.

### 8.3 Пташка (`bird`)
- `t0`: удары «крестом» — своя клетка и 4 соседа по стороне.
- Сразу после креста выбирается цель (раздел 9) и резервируется.
- В тике `t0 + T.bird_flight` — удар по цели тем же источником. Если Пташка несёт Рифф или Сабвуфер, вместо удара в цели срабатывает эта спецфишка (новый источник).
- Если целей нет — только крест.

### 8.4 Диско-шар (`disco`)
- Цвет X: при свапе с обычной фишкой — её цвет; иначе — самый частый цвет среди обычных фишек в `idle` (включая фишки под проводами).
- В `t0` шар переходит в `armed` на своём месте. Список L — обычные фишки цвета X в `idle` на момент `t0`, отсортированные по расстоянию Чебышёва от шара, затем по индексу.
- k-я цель (с нуля) бьётся в тике `t0 + T.disco_step·k`.
- В тике `t0 + T.disco_step·|L|` шар снимается, и его клетка получает удар.
- Если L пуст — сразу удар по своей клетке.

### 8.5 Комбо (свап двух спецфишек, центр — клетка `to`)

| | riff | sub | bird | disco |
|---|---|---|---|---|
| **riff** | «Крест»: разряды по ряду и колонке центра | «Тройной крест»: набухание `T.sub_swell`, затем разряды по рядам y−1, y, y+1 и колонкам x−1, x, x+1 | Пташка несёт Рифф | Цвет X → Риффы |
| **sub** | | «Бас-дроп»: как Сабвуфер, но радиус 3 (7×7) | Пташка несёт Сабвуфер | Цвет X → Сабвуферы |
| **bird** | | | «Трио»: крест в центре, затем три Пташки к трём разным целям, все бьют в `t0 + T.bird_flight` | Цвет X → Пташки |
| **disco** | | | | «Гранд-финал» |

- Один комбо-эффект — один источник. Крест не бьёт центр дважды.
- **«Цвет X → спецфишки»:**
  - X — самый частый цвет;
  - k-я фишка списка L (порядок из 8.4) превращается в спецфишку в состоянии `armed` в тике `t0 + T.transform_step·k`. Превращение засчитывается как сбор фишки цвета X;
  - Риффы по очереди получают оси h, v, h, v…;
  - после последнего превращения они срабатывают по очереди с шагом `T.fire_step`. Уже сработавшие от цепочки пропускаются.
- **«Тройной крест»**: разряд по ряду y+k выходит из клетки (x, y+k), по колонке x+k — из (x+k, y). Время удара — по формуле Риффа от точки выхода, со сдвигом на `T.sub_swell`.
- **«Гранд-финал»**: пауза `T.finale_pause`, затем каждая существующая клетка поля получает удар, кольцами Чебышёва от центра с шагом `T.ring`.

### 8.6 Цепочки
- Спецфишка, взведённая ударом `effect`, срабатывает через `T.chain` тиков в той клетке, где висит.
- Каждая спецфишка срабатывает один раз.
- Рифф сохраняет свою ось. Диско-шар от цепочки бьёт по самому частому цвету на момент срабатывания.

## 9. Цели Пташки

Кандидаты — существующие клетки не из текущего креста, не зарезервированные другой летящей Пташкой, без фишки в `clear` или `armed`.

**Одиночный удар.** Уровень полезности клетки:

| Уровень | Что в клетке |
|---|---|
| 5 | элемент цели `break`, который не ломается ударом `adjacent` (сейчас это `concrete`) |
| 4 | другой элемент цели `break` с остатком > 0; незажжённая плитка танцпола при цели `light`; обычная фишка цвета из `collect` с остатком > 0 |
| 3 | клетка прямо под микрофоном (та же колонка, y+1), если в ней обычная фишка и цель `deliver` не закрыта |
| 2 | любой другой блокер или фишка под проводами |
| 1 | любая обычная фишка в `idle` |

Выбор: максимальный уровень → максимальная «плотность» (число клеток уровня ≥3 в квадрате 3×3 вокруг) → случайно из потока `effects` среди равных (кандидаты по индексу).

**С грузом.** Для каждой клетки-кандидата считается сумма весов по площади груза: Сабвуфер — 5×5; Рифф — лучшая из двух осей, при равенстве `h`. Веса: уровни 4–5 → 10, уровень 3 → 6, уровень 2 → 2, уровень 1 → 1. Берётся максимум суммы, при равенстве — случайно из потока `effects`.

## 10. Гравитация, спавн, микрофоны

### 10.1 Назначение падений (шаг 5 тика)
Проход по рядам снизу вверх, в ряду — слева направо. Для каждой существующей пустой клетки `c` ищется ближайшее содержимое выше в той же колонке:

| Первое, что встретилось сверху | Результат |
|---|---|
| пустота (несуществующая клетка) | `blocked` |
| пустые клетки до спавнера на вершине отрезка | `spawn` |
| пустые клетки до вершины отрезка без спавнера | `blocked` |
| фишка regular/special/mic в `idle` или `fall` без проводов | `piece` |
| фишка в `clear`, `swap` или `armed` | `wait` |
| статический блокер или фишка под проводами | `blocked` |

Действия:
- **`piece` Q.** Q переписывается в клетку `c`: `offy += Δy·3600`. Если Q была `idle`, она переходит в `fall` со скоростью `T.fall_v0` и задержкой старта = числу фишек, уже начавших падение в этой колонке в этом тике. Метки — по правилу 1.3.3. Старая клетка Q пустеет и будет обработана позже в этом же проходе.
- **`spawn`.** Новая фишка ставится прямо в `c` в состоянии `fall`. Её визуальная позиция — на клетку выше спавнера, но не ближе чем на клетку к самой высокой падающей фишке этого отрезка колонки. Цвет — раздел 10.3.
- **`wait`.** Ничего не делать.
- **`blocked`.** Диагональ. Доноры — клетки (x−1, y−1) и (x+1, y−1); в чётных тиках сначала левый, в нечётных — правый. Донор D подходит, если его фишка подвижная, в `idle`, без проводов и **не может падать прямо**: клетка под D не существует или занята чем угодно. D переписывается в `c` со смещениями `offx = ±3600`, `offy = 3600` и переходит в `fall`. На одну пустую клетку — не больше одного донора.

### 10.2 Движение (шаг 6)
По каждой колонке падающие фишки обрабатываются снизу вверх:
1. Если задержка > 0 — уменьшить её и пропустить фишку.
2. `vy = min(vy + T.fall_acc, T.fall_vmax)`, затем `offy -= vy`. Если `offx ≠ 0`, `|offx|` уменьшается на `vy`, но не ниже 0.
3. Ограничение: фишка не может быть ближе чем на 3600 единиц к падающей фишке под ней в той же колонке. При упоре её скорость = скорости нижней.
4. При `offy ≤ 0`: смещения обнуляются, фишка становится `idle`, запоминает тик приземления, поле «грязное», событие `land`.

### 10.3 Цвет новой фишки
- Базово — по весам уровня (поток `spawn`).
- **Помощь застрявшим:** после 3–4 поражений подряд на уровне с вероятностью 5%, после 5 и больше — с вероятностью 10% (проверка `int(100)`) цвет принудительно «полезный»:
  - цвет цели `collect` с наибольшим остатком;
  - если таких целей нет — самый частый цвет на поле.
- Помощь работает только в пользу игрока, покупки на неё не влияют.

### 10.4 Микрофоны
- Спавнер ставит микрофон вместо цветной фишки, если одновременно:
  - выпущено микрофонов меньше `total` (стартовые считаются выпущенными);
  - на поле микрофонов меньше `on_board_max`;
  - с последнего выпуска прошло не меньше `gap_moves` ходов.
- За тик выпускается не больше одного микрофона — первым подходящим спавном в порядке обхода.
- Микрофон в `idle` на клетке-стойке сразу засчитывается: `clear` на `T.clear`, цель `deliver` −1, событие `mic_delivered`.

## 11. Покой и конец хода

**Поле в покое:**
- все фишки `idle`;
- нет активных эффектов и запланированных ударов;
- поле не «грязное»;
- в последнем проходе гравитации не было ни одного назначения.

**Очередь ходов.** Принятые свапы и тапы, кроме «возвращённых», ставятся в очередь конца хода.

**При покое** (шаг 8), если игра в `playing`:
1. Для каждого действия из очереди по порядку: если на уровне есть помехи и у действия нет `noise_hit`, одна помеха растёт.
   - Кандидаты — пары (помеха, соседняя по стороне обычная фишка в `idle` без проводов), по возрастанию индексов (помеха, потом фишка).
   - Пара выбирается потоком `effects`, фишка превращается в помеху, событие `noise_spread`.
   
   Очередь очищается.
2. Все цели выполнены — победа (раздел 13). Проверка идёт **первой**.
3. Иначе, если `moves_left == 0` — состояние `out_of_moves`.
4. Иначе, если нет ни одного хода (раздел 12) — перемешивание.

Выполнение всех целей в любой момент сразу переводит игру в `won_wait`: ввод блокируется, каскады доигрываются.

## 12. Ходы, перемешивание, подсказка

### 12.1 `has_move`
Истина, если есть спецфишка в `idle`. Иначе перебираются пары соседних клеток (вправо и вниз) по индексу. Пара подходит, если свап принимается по 5.1 (без учёта счётчика ходов) и виртуальный свап даёт матч через одну из двух клеток.

Для стартовой доски нужно «не меньше 3 ходов» — это число таких пар.

### 12.2 Перемешивание (поток `shuffle`)
- Кандидаты — обычные фишки в `idle` без проводов; клетки те же.
- До 50 попыток: перестановка Фишера–Йейтса. Попытка принимается, если после неё нет матчей и `has_move` истинно.
- Затем до 50 попыток перекраски цветами уровня с запретом матчей (как на старте).
- Если не вышло: случайная фишка-кандидат становится Риффом (ось h).
- Если кандидатов нет совсем: случайная помеха (если есть) снимается, и на её место ставится Рифф.
- Ход не тратится. Событие `shuffle` с перемещениями фишек. Поле «грязное».

### 12.3 Подсказка `game:hint()`
Считается по фишкам в `idle` и выбирает лучший ход по ярусам:

| Ярус | Ход |
|---|---|
| 4 | свап двух спецфишек |
| 3 | свап, создающий спецфишку |
| 2 | свап с прогрессом цели (в группе фишки цвета `collect`, клетки на незажжённом танцполе, соседство с блокером из `break`) или тап по спецфишке |
| 1 | любой ход |

Внутри яруса — больше клеток в предсказанной группе, затем меньший индекс первой клетки. Показ подсказки (5 с бездействия, покачивание) — забота клиента.

## 13. Победа, финальный концерт, поражение

1. **`won_wait`**: ввод закрыт, каскады идут до покоя.
2. **`concert`, фаза A.** Пусть n = `moves_left`. Для k = 1..n в тике `t + T.concert_step·k` случайная обычная фишка в `idle` без проводов (поток `effects`) превращается в Рифф (оси h, v по очереди): `moves_left -= 1`, +300 очков, событие `concert_riff`. Если кандидатов нет — оставшиеся превращения пропускаются.
3. **Фаза B.** После превращений все спецфишки в `idle` срабатывают по очереди, по индексу, с шагом `T.fire_step`.
4. **Фаза C.** При покое: если снова есть спецфишки в `idle` — фаза B ещё раз (не больше 20 кругов), иначе `complete`.

Итог уровня: очки, `moves_at_win` (сколько ходов было при победе — мета платит +5 монет за каждый), звёзды по сложности (`easy` и `medium` — 1, `hard` — 2, `super_hard` — 3).

- **`out_of_moves`**: клиент предлагает продолжение (`continue`) или сдачу (`give_up` → `lost`).
- **`skip`**: включает турбо до `complete`. Итог может отличаться очками от просмотренного концерта — это допустимо и записывается в реплей.

Визуальные тайминги (касание, сплющивание, частицы, надписи) живут в клиенте и на логику не влияют.

## 15. Тик

```
  1. (ввод уже применён между тиками)
  2. свапы и откаты, у которых закончился таймер (раздел 5.1)
  3. запланированные действия этого тика по порядку постановки:
     удары эффектов, срабатывания, превращения, перелёты
  4. фишки в clear с истёкшим таймером исчезают

  8. если поле в покое: обработка покоя (11) и фазы концерта (13)
```

## 17. Реплей и хеш
- **Реплей** = id и версия уровня, `seed`, `attempt`, `salt`, бустеры перед уровнем, уровень помощи, режим таймингов, список `{tick, cmd}`.
- Воспроизведение даёт те же события и тот же хеш состояния.
- **Хеш состояния** — детерминированная свёртка: по клеткам по индексу (вид, цвет, спецфишка, ось, hp слоёв, состояние), затем счётчики (ходы, очки, цели, тик, состояния генераторов).
- Золотые реплеи в `tests/golden/` проверяются на каждом прогоне тестов.
