# WP-11: Чарт и Группа

**Предложение и что сделано.** Вкладки «Группа» и «Чарт» больше не «Скоро»: это окна `gui/band.lua`, `gui/chart.lua` (общие части — `gui/social_kit.lua`), действия — `client/social.lua`, интерфейс — `client/services/social.lua`, правила — `meta/social.lua`, мок-сервер — `client/services/social_mock.lua`. Реального сервера нет: по умолчанию провайдер «недоступен», окна честно пишут «не подключено» (не ошибка).
- **Чарт:** недельный (звёзды с понедельника 00:00 UTC), за всё время, моя группа (роль «друзей»). Топ-100, моя строка закреплена внизу, прокрутка по строкам (колесо, перетаскивание, стрелки), значок района (цветной кружок с номером), медали 1–3. Подъём в рейтинге: строка считает место от старого к новому, зелёная метка «+N», вспышка; один раз за загрузку. Без входа: «Войди, чтобы увидеть чарт» с кнопкой (открывает окно аккаунта); без сети: «Нет связи» и «Ещё раз».
- **Группа:** карточка (название, код, N из 20), шкала недельной цели (30★ на участника, минимум 60★), список участников со звёздами недели, роли лидер/участник, «Создать» (название выбирается из списков слов), «Вступить по коду» (код берётся из буфера/окошка, подходит и целый текст приглашения), «Пригласить» (копирует текст с кодом), «Выйти» (с подтверждением; лидером становится вступивший раньше всех; пустая группа удаляется), лидер может исключить участника (касание строки). Помощь жизнями: «Попросить жизнь» → у друга на строке сердце → жизнь приходит при открытии окна группы (`Meta:gift_lives`, не выше максимума). Чата нет.
- **Безопасность и приватность:** игрок показывает другим только игровое имя, аватар (из 12), номер района и счётчики звёзд. Имя НЕ вводится: это «прилагательное + существительное + число» из фиксированных списков (у каждого игрока на своём языке), поэтому в нём не бывает настоящих имён, почты, ссылок и грубостей. Почта и uid аккаунта другим не показываются (в провайдере нужен отдельный публичный id, см. ниже).
- **Защита от накрутки** (`meta/social.lua`, сервер обязан применять те же правила): звёзд не больше 3 за достигнутый уровень (+суперзвёзды), рост не больше 30★ в сутки, в недельный счёт идёт не больше 120★, нарушение = обрезка + метка; 3 метки — игрок пропадает из публичного чарта (себе виден с пояснением «проверяем результат»); число меньше прежнего игнорируется без метки. Помощь жизнями: отправить ≤5 в сутки, получить ≤3 в сутки, один друг — одна жизнь на просьбу.
- Сохранение игры не менялось (`Meta:gift_lives` меняет только число жизней). Новые тексты ru/en/ko (ko перевёл сам, нужна проверка носителем; шрифты ko пересобраны `gen_defold.py`).

## Правила доступа к данным (для Firestore) и что включить в провайдере
1. Сделать `client/services/social_web.lua` по образцу `auth_web.lua` с теми же методами, что у мока (`profile_get/set, report, chart, band_get/create/join/leave/kick, help_request/send/claim`, вызов `provider:op(uid, ..., cb)`), и `web/glow_social.js`. Включить: `social.set_provider(...)` в `main/app.script` рядом с `auth.set_provider`.
2. Коллекции: `players/{pid}` (name{a,n,d}, avatar, district, total, level, day, day_gain, week, week_base, flags; `owner` = auth uid), `bands/{code}` (name{a,n}, leader, members{pid: seq}), `help/{pid}`. Публичный `pid` — случайный, не равен auth uid; почта и uid в этих документах не хранятся.
3. Правила: читать `players` и `bands` может любой вошедший; писать `players/{pid}` может только владелец и только через проверку: `total` не уменьшается, `total ≤ 3·level + super`, рост ≤ 30/сутки (лучше Cloud Function; правила Firestore не умеют считать «за сутки» без серверной метки времени `request.time` — использовать её). Группы меняются только транзакцией (вступление: проверка ≤20 и свободного кода; выход: передача лидерства). Запретить запись чужих документов, удаление чужих групп и любые поля вне схемы (`keys().hasOnly(...)`). Чарт топ-100: индекс по `weekScore desc, total desc`, читать `limit(100)`.
4. Недельный сброс не нужен физически: счёт недели = `total − week_base`, база обновляется при первом отчёте новой недели (как в `rules.report`).
5. Проверка: два аккаунта, у каждого профиль, создать группу, вступить по коду, выйти, подъём в чарте; затем те же шаги на мок-тестах как эталон поведения.

## Решения (мои) и вопросы продюсеру
1. Чарт и группа — окна города (как магазин), а не отдельные экраны: проще и безопаснее, прокрутка по строкам. Друзей отдельно нет: «друзья» = моя группа.
2. Имя выбирается из списков слов: нет модерации и личных данных. Хотите ввод своего имени — нужна модерация (скажите).
3. **Награды недели:** не выдаются. Предложение: топ-10 недели и выполненная цель группы дают монеты/бустер через сундук; нужен ваш размер наград и баланс (иначе накрутка обесценит экономику).
4. **Размер группы:** сейчас 20 (`BAND_MAX`), цель 30★ на участника (`BAND_GOAL_PER_MEMBER`); верно ли?
5. Нужна ли политика конфиденциальности до включения (чарт показывает игровое имя и звёзды)?
