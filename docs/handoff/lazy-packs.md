# Картинки районов по требованию (ветка `lazy-packs`, 20.11.2026)

**Зачем.** Игрокам с медленной связью до GitHub (Узбекистан) приходилось скачать весь архив (88,9 МБ) до первого кадра. Решение продюсера: при старте качается только нужное первому району, остальное — когда игрок до него дошёл.

**Сделано.**
- `tools/gen_defold.py` по `content/districts.json` делит свободные картинки: общие (`backgrounds`, `bit`, `logo`, `notebook`) и всё первого района (сейчас `cafe`) — в архиве; картинки любого другого района (`districts/<id>/*`, `mapbg/bg_<id>`, `mapbg/gate_<id>`) — «удалённые»: в реестре `remote = "packs/<путь>?v=<хеш>"`, `bytes`, `district`, список по районам `packs` (сначала фон комнаты, «призраки», фон уровня). Кода под район нет: районы части 2 делятся сами.
- Только веб: `assets/gen/web.settings` (bob `--settings`) сужает `custom_resources` и ставит `glow.packs = 1`; `game.project`, другие платформы и тесты читают всё из архива, как раньше. `tools/build_web.sh` кладёт файлы из `assets/gen/web_packs.txt` в `packs/` рядом с `index.html` (адрес считается от страницы, сайт живёт в `/game/`).
- `client/packs.lua` (чистый Lua, HTTP и часы подставляются): приоритеты, 2 запроса сразу, срок запроса растёт с размером файла (30 с + время при 6 КБ/с: плитке карты 1 МБ около 200 с), 3 попытки с паузой, затем новый круг через 20 с…5 мин; после 6 неудач подряд общая пауза («нет связи»); память до 16 МБ, освобождаются дальние районы, район игрока и следующий — никогда. Запросы делает только `main/app.script`; раз в секунду он просит район города, район уровня и следующий. Заставка не ждёт.
- `Scene:loose_texture` (`client/ui.lua`) берёт скачанные байты. Город: плашка «Загружаем район… N%» / «Нет связи: картинки появятся позже» (ru/en/ko), комната и карточка задачи перерисовываются, когда картинки пришли; игра работает всё время. Карта: плитки цвета района и табличка с названием вместо ворот, заменяются по приходу. Уровень: общий фон, пока нет своего.
- `web/packs_sw.js`: GitHub Pages отдаёт `max-age=600`, а ETag всех файлов меняется при каждой выкладке, так что кэш браузера скачал бы после релиза все картинки заново. Service worker отдаёт сохранённую картинку `packs/…?v=` без сети; сохраняет, только если SHA-1 совпал с `v`. Без SW (старые браузеры) всё работает через обычный кэш. SW — сверх задачи и остаётся в браузерах игроков; он отдельным коммитом `a089780`, его можно убрать.

**Размеры, release.** Архив 88 882 482 → 51 551 314 байт (43 → 25 кусков по 2 МБ); первая загрузка (страница, движок, архив) 91 599 702 → 54 268 931 байт (сборка `build_web.sh` без `SKIP_GEN`); `packs/` 254 файла, 37 348 500 байт.

**Проверено.** `luajit tools/test/run.lua`: 2934 прошло, 30 упало — те же 30, что на исходной ветке (сравнено по именам); новые тесты `packs_test.lua` (12), `packs_split_test.lua` (6) и тесты на строгих заглушках (город: плашка и одна перерисовка, «нет связи»; карта: заглушки → картинки; фон уровня: общий → свой) зелёные, затронутые файлы (122 теста) и на настоящем Lua 5.1; `check_refs: ok`; `gen_defold --check` отличается только концами строк. Браузер (Chrome, debug, сайт по пути `/GLOW/`, скрипт `GLOW-tools/lazy_shots.mjs`, снимки `GLOW-tools/shots/lazy/`): свежий старт (уровень 1, город кафе и карта целиком из архива; в фоне качается район 2, первый запрос `packs/` — после загрузки архива); район 3 с задержкой ответов 3 с (плашка 0 % → комната, карточка; фон уровня 61: общий → свой); запросы заблокированы (город с «Нет связи», карта с заглушками, уровень 41 сыгран на общем фоне, 12 запросов за прогон, ошибок Lua 0); блок → связь вернулась (комната через 18 с); медленный канал 30 КБ/с (CDP): плитка карты 1,1 МБ шла 67 с и пришла без неудач и без ложного «нет связи», снимки `slow_map_early/later` (со сроком 60 с она бы сорвалась — исправлено); пути города при блоке: листание к району 2, концертный вид, окно концерта — ошибок 0; перезагрузка в районе 5 (первые запросы — `garage`); второй визит с SW (42 картинки из SW, 0 запросов в сеть); release-сборка (старт, 19 запросов района 2, ошибок 0).

**Не проверено.** Телефоны и встроенные браузеры (Telegram и т.п.); настоящая выкладка на GitHub Pages (заголовки только прочитаны curl); вытеснение по бюджету памяти в движке (только юнит-тест); весь набор тестов на Lua 5.1 (только затронутые файлы); `tools/qa/web_screens.mjs --rooms-only` запускался и остановился на окне аккаунта первого запуска, которое скрипт не закрывает (скрипт старше этого окна; на исходной ветке не перепроверено).

**Музыка (фаза 2) — не внедрена.** В движке 1.13.1 есть `resource.set_sound` и `resource.create_sound_data`. Проба в настоящей HTML5-сборке: `set_sound` байтами из `http.request` подменяет данные песни для следующего запуска (тишина → RMS ровно 0, возврат байтов → как в контроле), ошибок нет; уже играющий звук доигрывает старые данные. Не внедрено: чтобы убрать песни из веб-архива, компоненты в `audio.go` (один на все платформы) должны ссылаться на тихие заглушки, а настоящие песни грузиться при запуске везде, и `main/audio.script` должен ждать данных (тишина, старт по приходу, правила кроссфейда) — это переделка ядра звука, не «очевидно надёжная». Рекомендация — отдельной задачей: заглушка на песню в `assets/gen/songs/`, настоящие песни как custom resources (на вебе в `packs/`), `set_sound` перед первым запуском, «загрузка» в автомате, проверка в браузере по `sound.get_rms`, как в пробе; потом так же стемы районов (12 МБ) вместе с картинками района. Замечено попутно: после `music_stop` и повторного `music` той же песни RMS ~0,002 против ~0,05 при первом запуске (и без подмены) — на слух не проверялось.

**Вопросы продюсеру.** Бюджет 16 МБ и подкачка «район + следующий» — значения по умолчанию; проверить на телефоне с медленной связью.
