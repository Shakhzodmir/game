# WP-8: комнаты и анимации персонажа

**Сделано.** (1) `content/animations.json` + `client/anim.lua` (чистая Lua): состояния Бита данными (idle ×3 варианта по случайному интервалу, танец a/b, радость, удивление, сон, пишет, слушает, машет), события (`task_done`, `level_won`, `note_collected`, `tap`, `notebook`, `headphones`, `hello`), скука 45 с → сон, касание будит «удивлением», танец идёт по часам трека (`audio.status.clock/bpm`, поле `bpm` добавлено в `main/audio.script`), звуки по кадрам, покачивание (дыхание, качание, подскок на доле); `client/bit.lua` играет кадры, API прежний (`cheer/worry/dance/mood_for/set/poke/stop`, новое `event/touch/release`). Для WP-9: `bit:event("notebook")` … `bit:release()`. (2) Комнаты: `content/rooms.json` + `screens/town/life.lua`: слои bg/mid/items/over/fg с параллаксом при листании и лёгким дрейфом, по 6–7 живых деталей на район (огни, пар, нотки, пылинки/искры/конфетти/угли, лучи, боке; часть оживает, когда задача куплена), качание предметов по данным (`items` в animations.json), плавная смена «день/концерт» (0,6 с), волна света и вспышка огней при покупке, Бит танцует в концерте. Узлов на комнату ≤ 44 (в тесте 17–28). (3) `tools/art/install_ready.py` (+`installed.py`): ставит кадры Бита и комнаты из `assets/art_ready` в `assets/images`, пишет `assets/art_ready/installed.json`; `gen_art.py` такие файлы не рисует и не удаляет. (4) Процедурные кадры Бита (`tools/art/bit.py`, 48 штук), тесты, QA-снимки.

**Проверено.** `./tools/test.sh` (результат ниже), новые тесты: `anim_test` (19), `rooms_test` (7: данные, бюджет узлов и анимаций во всех районах и видах, ожидание задачи, перекрёстное затухание, параллакс, волна, reduced motion), `install_ready_test` (3). `gen_defold --check`, `check_refs`, `check_syntax` чисты. Установка проверена вживую на 54 файлах из ветки `orch` (`assets/art_ready`): `gen_art.py` их не тронул, затем откат. **Не запускалось:** браузер (`web_screens.mjs --rooms-only` написан, не гонялся; нужен bob), устройства; вид комнат глазами не смотрел.

**Имена и размеры, которые ждёт код** (бриф A1/B1 совпал с кодом, расхождений нет). Бит: `bit_<анимация>_<n>.png` в `art_ready/bit` → `assets/images/bit/<анимация>_<n>.png`, 256×256 RGBA, одна линия земли; кадры: idle_breathe 4, idle_look 4, dance_a 6, dance_b 6, cheer 6, surprised 4, sleepy 4, write 6, listen 4, wave 4 (ставится только полный комплект анимации). Комнаты: `room_<район>_day|concert.png` → `districts/<район>/bg.png|bg_concert.png`, 720×1280. Не заменённое остаётся заглушкой (у producer'а пока нет `bit_idle_breathe`: дыхание процедурное, стиль с остальными расходится, WP-12 стоит попросить дорисовать).

**Решения.** Бюджет картинок `gen_art.py` 10 → 12,5 МБ (48 кадров Бита ≈ 3 МБ); установленные producer'ом файлы в бюджет не входят (с 54 файлами всего 17 МБ: размер веб-сборки решать продюсеру). `import_incoming.py` в базе моей ветки не было (лежал только в `orch`): взят оттуда без правок, ошибок не нашёл. Проверка «арт обрезан по краю» не применяется к `bg.png`/`bg_concert.png` (картинки producer'а приходят RGBA). Текстуры кадров Бита грузятся по мере показа: до ≈14 МБ GPU, если показать все. Параллакс при листании и дрейф, а не от наклона/мыши (нет датчиков). Тест `meta_town_gui_test` ослаблен: «картинок Бита не больше, чем у него есть кадров».

**Осталось.** Прогнать `web_screens.mjs` и посмотреть комнаты; настоящие рисунки (WP-12); `level_won` в итогах уровня пока идёт старым `cheer` (событие готово, подключать не стал: не в задаче).

**Вопросы продюсеру.** 1) Допустим ли вес картинок ≈ 17 МБ с настоящими комнатами и кадрами Бита (сейчас 12 МБ)? 2) Должен ли Бит засыпать и на экране уровня (сейчас да, через 45 с без касаний)? 3) Нужны ли звуки на кадрах (сейчас только «land» у радости и тихий «tap» у удивления)?
