# WP-0: сохранение прогресса, конец контента, код сохранения

**Как хранится.** `client/save_io.lua`: `sys.get_save_file("glow", ...)`, файлы `save_current.sav` и `save_previous.sav` (на HTML5 это IndexedDB сайта). Обёртка `{glow_save = 1, data = <сохранение меты>}`. Запись: прежний `current` уходит в `previous`, потом пишется новый `current`. Мета при загрузке проверяет версию и сумму, идёт current → previous → пустое сохранение (`meta/save.lua`, `Meta.load`).
**Что может стереть прогресс.** (1) Смена `APP_ID`, имён файлов или `FORMAT`: игра перестанет видеть старые файлы. (2) Смена или удаление полей `save.fields`, рост `C.save_version` без миграции (`no_migration_from_N` → пустое сохранение). (3) Очистка данных сайта, другой браузер, другой компьютер, другой домен (IndexedDB привязана к origin: переезд с `shakhzodmir.github.io` = пусто). (4) Оба слота повреждены. Обычное обновление сборки прогресс не трогает: сохранение читается как есть, новые поля добавляются с умолчаниями; сохранение из более новой сборки читается, лишнее не теряется.
**Что сделано.**
- `tests/meta/save_lock_test.lua`: замок (APP_ID, файлы, FORMAT, порядок и состав `save.fields`, миграции для всех старых версий) и «игрок на 89-м» (88 побед через API меты; поле за полем после serialize/load, через файл-обёртку и через код; игра продолжается с 89-го). Миграций пока нет (версия 1), тест их проверит, когда они появятся.
- `meta/savecode.lua` + `tests/meta/savecode_test.lua`: код `GLOW1-` + base64url(флаг + данные, LZSS если короче) + 16 hex суммы. Только сохранение, ни ключей, ни адресов (тест на это). Отказы: пусто, префикс, версия, формат, сумма, обрезан, подделан, слишком длинный.
- Настройки: «Скопировать код сохранения» / «Ввести код сохранения» (`gui/settings.lua`, `client/platform.lua`: на вебе `navigator.clipboard` с запасным `window.prompt`, ввод через `prompt`; на десктопе `clipboard`). Окно подтверждения: уровни, монеты, звёзды, предупреждение «МЕНЬШЕ прогресса». Перед заменой текущее сохранение кладётся в `previous`; мета перезапускается без перезагрузки страницы (`app.replace_save`), затем экран заставки. Тесты: `tests/client/save_code_replay_test.lua`.
- Конец контента: `tests/meta/end_content_test.lua` (99 → 100 → «после»: награды и сундук 100-го платятся один раз, старты отказывают `all_done`, звёзд уровней хватает на весь город, концерты, сохранение). Найденная дыра: после 100-го не было ни одного действия (тупик). Сделан повтор пройденных уровней: кнопка в городе → окно `gui/replay.lua` (страницы по 20 уровней) → уровень как тренировка (без попытки меты: ни монет, ни звёзд, ни жизней; «Дальше» только в пределах пройденного).
**Что видит игрок на 100-м и после.** Окно итогов 100-го: звёзды, монеты, сундук 100-го («Открыть»), кнопки «Дальше» нет, есть «В город» и текст «Скоро новые уровни!». Город: вместо кнопки «Уровень N» кнопка «Пройденные уровни» (окно с текстом «Скоро новые уровни…» и выбором уровня). Звёзды и задачи районов работают, концерты тоже; сундук района платится. Поражение в тренировке жизнь не отнимает.
**Как перенести прогресс.** На старом компьютере: Настройки → «Скопировать код сохранения» (если буфер не дался, код появится в окошке: скопируйте его вручную). На новом: открыть игру → Настройки → «Ввести код сохранения» → вставить → проверить цифры → «Загрузить». Код храните как пароль к прогрессу.
**Проверено.** `./tools/test.sh`: 1992 теста зелёные на Lua 5.1 и LuaJIT; `check_refs`, `gen_defold.py --check`, `check_syntax.sh` чисты. **Не проверено:** живой прогон `tools/qa/web_screens.mjs` (проверка «экспорт → сброс → импорт» дописана, команды QA `save_code`, `save_import`): в этой среде нет `bob.jar` и браузера; запустить на CI/debug-сборке. `window.prompt`/`clipboard` на реальных браузерах не пробовались.
**Решения.** Код не шифруется (защита от опечаток, не от подделки: подделанное сохранение можно собрать и так, это одиночная игра). Replay без наград, чтобы не открывать ферму монет. Менялся только текст кнопки города; ключ `win.debug` заменён на `win.practice`.
