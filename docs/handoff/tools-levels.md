## Что сделано
- **README сверен с кодом** построчно. Найдено и исправлено:

- **Новое:** кэш результатов (`--work`, ключ — текст уровня без `moves`, бот, бюджет и контрольная сумма `core/` и `tools/bot/`; N в ключ не входит, партия k зависит только от сида k, поэтому пробный `--n 100` достраивается до `--n 300`); файлы результатов уровней вместо одного JSON из рабочего процесса; `--write` проверяет контрольную сумму файла, пишет атомарно и требует N ≥ 100 (или `--force`); флаг `stuck_games` и счётчики исходов партий в JSON; в тексте ошибки партии — сид и команда для повтора; `validate` на всём каталоге называет отсутствующие уровни из 1–100; код выхода 1/2.

## Цифры (подробно в `tools/README.md`)
- 70 существующих уровней, жадный бот, N = 100: все 7000 партий кончились победой, тупиков и зависаний нет; `strong` на N = 4 тоже без падений. 0,05–0,39 с на партию (в среднем 0,15 с), около 18 клонов на ход, 47% времени — `deepcopy` внутри `clone()`.
- Полный прогон 100 уровней, N = 300: около 76 минут процессорного времени, 25–27 минут настенного при `--jobs 3` (19–20 при 4). Пробный `--n 100`: 8–9 минут, итоговый после него ещё 17. Порог в 90 минут не достигнут, ускорять ботов не пришлось.
- На 70 уровнях при N = 100 ни одного `off_corridor`/`too_hard`/`too_easy`: easy 87–93%, medium 65–71%, hard 40–47%, super_hard 24–25%; `outside_band` у 24 уровней (у 1–10 M равен 6–14), `near_miss_low` у 5.

## Решения для decisions.md (оркестратор вносит)
1. Результат подбора кэшируется по содержимому: уровень, бот, бюджет, исходники ядра и ботов.
2. `--write` только при N ≥ 100 (в обход — `--force`), только для файла, не менявшегося после игры.
3. Отчёты подбора лежат в `docs/levels/`; в `content/` ничего не пишется.

## Что осталось и риски
- Ядро: `Game:clone()` (универсальный `deepcopy`) — почти половина времени подбора. Микротест: объекты поля одним конструктором таблицы дают клон 65 мкс вместо 120 (подбор быстрее на 20–25%, прогон 100 уровней около 20 минут вместо 25); универсальные приёмы (`table.new`, `next`) выигрыша не дали, `unpack` для массивов даёт 100 мкс. Не сделано: `core/` не мой.
- Жадный бот, вероятно, сильнее обычного игрока: подобранные M — оценка снизу. Для 1–10 и ещё 14 уровней M < 20 (`outside_band`): цели малы для правила плана «20–35 ходов».
- Для 71–100 прогона ещё не было (файлов нет). Первый полный прогон — по порядку из README (пробный `--n 100` → правка флагованных → `--n 300` → `--write`).
- Время зависит от нагрузки машины: при нагрузке около 10 на 4 ядра было втрое дольше.
- Полный набор на момент сдачи зелёный: 1352 (Lua 5.1) и 1354 (LuaJIT). В корне репозитория лежит чужой `luac.out` (след `luac -l` из чьего-то скрипта покрытия): не коммитить.
