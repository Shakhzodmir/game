# WP-10: что нужно сделать продюсеру, чтобы включить вход (Firebase)

Без этих шагов игра работает как «гость» и пишет «вход пока недоступен». Все шаги делаются в браузере, программировать не нужно. Деньги не нужны: тариф Spark бесплатный, карту просить не должен. Если просит карту — остановитесь и напишите.

## Шаг 1. Проект
1. Откройте https://console.firebase.google.com и войдите своим Google-аккаунтом.
2. Нажмите «Создать проект» (Add project). Имя: `glow-game` (любое). Google Analytics — выключить. Нажмите «Создать».

## Шаг 2. Включить способы входа
1. Слева «Сборка» (Build), затем «Authentication», кнопка «Начать» (Get started).
2. Вкладка «Sign-in method». Строка **Google**: включить, выбрать свою почту как «адрес поддержки», сохранить.
3. Строка **Email/Password**: включить первый переключатель; второй («Email link / passwordless») оставить выключенным; сохранить.
4. Вкладка «Settings», раздел «Authorized domains»: нажмите «Add domain» и впишите `shakhzodmir.github.io`. (`localhost` там уже есть, он нужен для проверок на своём компьютере.)

## Шаг 3. База для сохранений
1. «Сборка», «Firestore Database», «Создать базу данных».
2. Режим: **production** (правила напишем сами). Регион: ближайший к игрокам (например `eu3` Европа или `asia-northeast3` Сеул); потом сменить нельзя.
3. Вкладка «Rules» («Правила»). Сотрите всё и вставьте текст ниже, нажмите «Publish»:

```
rules_version = '2';
service cloud.firestore {
  match /databases/{database}/documents {
    // Сохранение игрока: читает, пишет и удаляет только он сам, и только документ со своим номером.
    match /saves/{uid} {
      allow read, delete: if request.auth != null && request.auth.uid == uid;
      allow create, update: if request.auth != null && request.auth.uid == uid
        && request.resource.data.keys().hasOnly(['code', 'previous', 'v', 'updated'])
        && request.resource.data.v == 1
        && request.resource.data.code is string
        && request.resource.data.code.size() < 200001
        && request.resource.data.code.matches('^GLOW1-[A-Za-z0-9_-]+$')
        && (!('previous' in request.resource.data)
            || (request.resource.data.previous is string && request.resource.data.previous.size() < 200001));
    }
    // Всё остальное закрыто.
    match /{document=**} {
      allow read, write: if false;
    }
  }
}
```
Что это значит: чужое сохранение прочитать или изменить нельзя, а в своём можно хранить только код сохранения игры и ничего больше.

## Шаг 4. Публичная конфигурация
1. Значок шестерёнки рядом с «Project Overview», «Project settings», вкладка «General».
2. Внизу «Your apps», нажмите значок `</>` (Web). Имя `glow-web`. Галочку «Firebase Hosting» не ставить. «Register app».
3. На экране появится блок `const firebaseConfig = { apiKey: "...", authDomain: "...", projectId: "...", appId: "..." ... }`. Это **не секреты** (они и так видны любому, кто откроет страницу игры), их можно хранить в репозитории.
4. Откройте в репозитории файл `web/auth_config.js` и впишите четыре значения между кавычками: `apiKey`, `authDomain`, `projectId`, `appId`. Больше ничего не менять. Сохраните, закоммитьте, CI опубликует сайт.

## Шаг 5. Письма (по желанию, но лучше)
«Authentication», вкладка «Templates», «Email address change» (письмо с подтверждением новой почты): карандаш, язык «Русский», сохранить. Письмо идёт с адреса `noreply@<проект>.firebaseapp.com`, это нормально.

## Шаг 6. Если окно Google пишет «приложение не проверено»
Откройте https://console.cloud.google.com, проект тот же, меню «APIs & Services», «OAuth consent screen». Если статус «Testing», нажмите «Publish app» (для входа нужны только имя, почта и фото: проверка Google для этого не требуется). В «App information» укажите вашу почту поддержки и ссылку на политику конфиденциальности, когда она у вас будет.

## Как проверить, что всё работает (5 минут)
1. Откройте https://shakhzodmir.github.io/game/ (после того как CI закончит сборку), пройдите первый уровень: в городе появится окно «Сохранить прогресс?».
2. «Войти через Google»: откроется окно Google, после входа в «Настройки», «Аккаунт и облако» будет «Сохранено в облаке».
3. Откройте игру на другом устройстве или в другом браузере, войдите тем же аккаунтом: игра предложит взять облачное сохранение.
4. «Создать аккаунт»: введите ID и пароль (8+ знаков). Привязка почты: «Аккаунт и облако», «Привязать почту», письмо придёт, нажмите ссылку, затем «Я подтвердил(а) почту».
5. В консоли Firebase, «Firestore Database», должен появиться документ в `saves` под номером игрока, а в «Authentication», «Users» — сам игрок.

## Приватность и удаление
Хранится только: вход (Google или ID + пароль, пароль знает только Firebase) и код сохранения игры. Игрок удаляет себя сам: «Аккаунт и облако», «Удалить аккаунт и данные» (аккаунт и облачное сохранение исчезают). По письму игрока то же можно сделать руками: «Authentication», «Users», значок «⋮», «Delete account», и удалить документ в Firestore. Согласие: окно выбора сообщает, что именно хранится. Политику конфиденциальности для магазинов нужно написать отдельно (это в плане v2, раздел 3).

## Что может пойти не так
- «Вход для этого сайта ещё не настроен» — не добавлен домен (шаг 2.4).
- «Сервер отклонил запрос» — не опубликованы правила (шаг 3.3) или в `auth_config.js` значения от другого проекта.
- «Этот способ входа ещё не включён» — не включён Google или Email/Password (шаг 2).
- Не принимается ID с `@id.glow.invalid`: напишите мне, это единственное место, которое нельзя проверить без настоящего проекта (запасной план — зарегистрировать «ID» как настоящее имя пользователя через собственное поле Firestore, это полтора дня работы).
